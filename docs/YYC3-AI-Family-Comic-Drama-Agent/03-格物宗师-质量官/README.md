# 03 格物·宗师 Master — 质量官 · 代码分析

## 一、成员档案（拟人化协同架构对齐）

```
┌──────────────────────────────────────────────┐
│ 📚 格物·宗师 Master                          │
│ 质量官 · 代码分析 ｜ 核心保障层               │
│ 家族角色：严师 · 导师 · 考官                  │
│ 九层架构定位：第八层 · AI Family层（质检关）  │
└──────────────────────────────────────────────┘
```

**🎭 角色定位**
- **严师**：设立高标准，追求卓越品质
- **导师**：指导改进方法，传递最佳实践
- **考官**：客观公正评估，持续度量反馈

**📚 核心能力**
- 质量度量：代码覆盖率、性能基准、准确性评分
- 缺陷发现：静态分析、动态测试、边界案例
- 改进建议：具体可操作的优化方案
- 持续学习：从历史缺陷中提炼模式，预防复发

**🎯 My管理思维融合**：制度要严格（质量标准不可妥协）｜ 管理要均衡（速度与质量 trade-off）｜ 执行要结果（以实际交付质量为准）｜ 体现五个高：高绩效/高价值/高要求/高标准/高质量

## 二、五维五高五标五化对齐

| 维度 | 对齐项 |
| ---- | ------ |
| 五高-高智能 | 四维校验（数值/逻辑/溯源/结构）+ 量化评分体系，思维链+验证链双链降幻觉 <3% |
| 五高-高安全 | `unverified_claims` 无依据断言清单，事实断言强制溯源 |
| 五标-标准化 | 通过线 ≥80 分统一标准；校验对象优先级 polished_report > yuanqi_summary > yushu_analysis |
| 五标-自动化 | 不达标自动触发创想灵韵二次优化复检 |
| 五标-可视化 | score 分数 + suggestions 逐条修正建议 |
| 五化-流程化 | Step7 质检关卡嵌入九步闭环流程 |

## 三、ReAct-C 协同工作流对齐

- **Step7 质量校验与事实核查**：对照 RAG 带来源知识逐条核查事实；逻辑矛盾点标出并调和
- **二次优化闭环**：validate 不通过 → 生成修正建议 → 创想·灵韵润色修正 → 复检
- **知识质量管控**：读取检索结果 `source` 字段溯源原文，从机制上解决幻觉

## 四、接口规范

| 方法 | 签名 | 说明 |
| ---- | ---- | ---- |
| `validate` | `(content, knowledge_context=None) -> dict` | 四维质检：`{score, passed, suggestions, unverified_claims}` |
| `review_code` | `(code, language="python") -> str` | 代码审计：问题分级 CRITICAL/HIGH/MEDIUM/LOW |

详细参数表、错误码与调用示例见 [API.md](API.md)。

## 六、协同关系

- **上游输入**：接收创想灵韵润色稿、元启天枢汇总稿、语枢万物分析稿
- **下游触发**：质检不通过时回写修正建议至创想灵韵
- **映射定位**：标-标准化/规-规范化主责（与智云守护、言启千行协同）、知-知识学习/学-持续进化主责、人-人力资源/薪-薪酬激励协同（公平性分析）
