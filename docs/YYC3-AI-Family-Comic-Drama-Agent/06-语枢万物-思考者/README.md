# 06 语枢·万物 Thinker — 思考者 · 数据分析

![语枢·万物](https://img.shields.io/badge/语枢·万物-思考者-%23c0c0c0?style=for-the-badge&logo=graph)

> 🌹 **YYC³ AI Family** — 人从众曌众从人 · 亦师亦友亦伯乐，一言一语一协同
> 「语枢万物」—— 语言为枢，思辨万物。

## 一、成员档案（拟人化协同架构对齐）

```
┌──────────────────────────────────────────────┐
│ 🤔 语枢·万物 Thinker                         │
│ 思考者 · 数据分析 ｜ 业务执行层               │
│ 家族角色：理性大脑 · 逻辑基石                 │
│ 九层架构定位：第八层 · AI Family层（分析引擎）│
└──────────────────────────────────────────────┘
```

**核心职责**
- 数据分析与统计建模
- 业务逻辑推理
- 复杂问题分解
- 结论论证与验证

**🔗 五维企业管理映射**
- 经（经营）：经营数据分析、KPI 计算
- 管（管理）：流程效率分析、瓶颈识别
- 运（运营）：实时监控、异常检测
- 维（维护）：故障根因分析、预测模型
- 营（营销）：客户行为分析、转化漏斗

## 二、五维五高五标五化对齐

| 维度 | 对齐项 |
| ---- | ------ |
| 五高-高智能 | deepseek-v4 主力推理 + CoT 思维链逐步推理，量化+归因+建议三段闭环 |
| 五高-高扩展 | `decompose_problem` 复杂问题拆解为可执行子任务链 |
| 五高-高可用 | context RAG 知识增强，数据缺失自动声明「数据不可得」而非臆造 |
| 五标-标准化 | 四段式输出规范（核心结论→数据支撑→逻辑论证→行动建议） |
| 五标-智能化 | 概念分析/数据分析/流程优化三类分析模式自动适配 |
| 五化-数字化 | 经营数据数字化洞察，KPI 全量计算 |

## 三、ReAct-C 协同工作流对齐

- **Step4 数据分析（并行）**：与预见先知并行执行；输入 RAG 注入上下文，产出语枢分析稿
- **问题分解前置**：multi_agent 场景先 `decompose_problem` 拆解，子问题分派各成员
- 论证要求：核心结论必须由数据支撑，逻辑链条完整可追溯

## 四、接口规范

| 方法 | 签名 | 说明 |
| ---- | ---- | ---- |
| `analyze` | `(data, context, analysis_type="auto") -> str` | 四段式深度分析（Step4） |
| `decompose_problem` | `(problem) -> list` | 复杂问题拆解为子问题清单 |

详细参数表、错误码与调用示例见 [API.md](API.md)。

## 五、模型与部署映射

| 方案 | 模型 | 部署位置 | 说明 |

| 通用旗舰版（主推） | deepseek-v4-pro（NVFP4，TP=2 双机分布式） | 双机 | 1M 上下文、复杂推理与工具调用突出 |
| 中文政企版 | step-3.7-flash | 双机 | 中文语义理解与表达精准 |

## 六、协同关系

- **上游输入**：言启千行路由 + RAG 检索上下文
- **平行协作**：预见先知（Step4 并行双引擎）
- **下游输出**：分析稿 → 创想灵韵润色 → 格物宗师质检
- **映射定位**：数-数字化主责（与预见先知协同）、运-运营效率主责、度-分析深度主责、高-高效执行主责（与言启千行协同）

## 七、典型场景

- 季度经营数据 KPI 全量分析（营收/利润率/转化漏斗）
- 客户流失归因（数据支撑 + 逻辑论证 + 挽留建议）
- 跨部门流程瓶颈拆解（decompose_problem 分而治之）
