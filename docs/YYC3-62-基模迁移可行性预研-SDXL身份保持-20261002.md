# 基模迁移可行性预研：SDXL 系身份保持（InstantID/PuLID）

## 一、预研动因与目标

- **动因**：SD15 模型族内 0.85 均值门槛无一达标（FaceID PlusV2 组合最优 mean 0.8248，G4-20261002 留证）；模型族内优化已到顶，基模迁移是破局唯一路径（36.4 TOP3 勘察结论）。
- **目标**：回答三个问题——①资源够不够（显存/耗时预算）；②迁移动多大（adapter/LoRA/评测影响面）；③怎么落（分阶段路线与风险）。

## 二、候选技术勘察（2026-10-02 公开资料）

### 2.1 三技术资源对照（SDXL，1024x1024/30 步口径）

| 指标 | InstantID | PuLID | FaceID（现役同族） |
| ---- | --------- | ----- | ------------------ |
| 单张生成耗时 | 约 28s | 约 35s | 约 25s |
| 显存占用 | 约 8.5GB（12-16GB 推荐） | 约 10.2GB（12GB+/16GB 推荐） | 约 7.8GB |
| 模型下载量 | 约 1.8GB + ControlNet + antelopev2 | 约 2.3GB | 1.2GB（SD15 版已落库） |
| 技术特征 | IdentityNet + Image Adapter，零样本单图强 ID | 纯 ID 嵌入对齐，画质自然度口碑佳 | IPAdapter FaceID，弱 IPA 路线 |

来源：apatero.com ComfyUI 三技术对比（2025-10）、clore.ai InstantID 部署指南（12GB Basic/16GB HQ）、arXiv 2401.07519（InstantID 论文：插件式支持 SD1.5/SDXL，但 ComfyUI 社区实装节点为 SDXL 专属——与项目 36 轮勘察结论一致）。

### 2.2 基模候选

| 候选 | 理由 | 风险 |
| ---- | ---- | ---- |
| **DreamShaper XL（首选）** | 与现役 DreamShaper 8 同作者同风格谱系，画风迁移断点最小；SDXL 生态 LoRA/ControlNet 资产最厚 | 需 civitai/hf-mirror 下载约 6.9GB；SDXL 系须重训角色 LoRA |
| Juggernaut XL（备选） | 写实向口碑稳 | 画风与现役水墨古风偏差较大 |
| FLUX.1 dev（观察项） | 多参考一致性原生支持（FLUX.2 已至 10 参考图）；12B 参数 | FP16 约 24GB，量化后仍 8-16GB；非 UNet 架构，IPAdapter 系插件生态不通用，迁移成本最高 |

## 三、资源预算（结合本机实态）

### 3.1 Mac M4 Max（编排/静态镜生产节点）

- 统一内存架构无独立显存硬墙；实测基线：SD15 512px 25 步约 8-10s/张。
- SDXL 1024 25 步预估 30-60s/张（社区 M 系经验区间；届时以冒烟实测修正）。
- **产能影响**：3 集 x 3 镜批量从约 9-12 分钟放大至约 5-9 分钟纯生成耗时（叠加 IPAdapter/InstantID 开销后更高），夜批窗口仍可容纳，但 G4-006 批量护航超时参数须上调（现 900s/镜充足）。
- 模型装载内存：SDXL FP16 约 7GB + InstantID 组件约 2-3GB，统一内存充裕。

### 3.2 yyc3-n1 DGX Spark（GB10，训练节点）

- 128GB 统一显存：SDXL LoRA 重训无容量压力；kohya sd-scripts 对 SDXL 训练链路成熟（--sdxl_model 口径）。
- 预算：dim32 SDXL LoRA 单 epoch 耗时约为 SD15 的 2.5-4 倍（UNet 3.5B vs 0.86B），v2 数据集 19 图 10 repeats 约 190 步/epoch，预估 30-50 分钟/epoch（n1 实测修正）。

### 3.3 下载通道

- hf-mirror.com 可达（FaceID PlusV2 已验证）；DreamShaper XL 备选 civitai（须 API token 或直链）。

## 四、迁移影响面评估

| 层 | 影响 | 工作量定性 |
| -- | ---- | ---------- |
| 生产 adapter（drama_stage_adapter） | CheckpointLoaderSimple 换 XL ckpt；身份节点 10/11/12 换 ApplyInstantID（insightface antelopev2 + InstantIDModel/InstantIDAttentionPipe）或 ApplyPuLID；可沿用 v1.3 双档位模式加 "instantid" 档 | 工作流构建器一档增量，口径同 faceid 档先例 |
| 角色 LoRA | **SD15 结构（UNet 576 keys）与 SDXL 不兼容，全量重训**；v2 数据集（19 图）为已证优数据集直接复用；384 图上采样教训沿用 | n1 一轮训练 + 4 种子评测（协议复用） |
| 评测协议 | 4 漂移种子 x insightface 余弦 vs 历史设定图本体——**完全复用，零变更**；参考系锚定规则沿用 | 零 |
| 动态镜 H3 | 图生视频输入为 PNG，与静态镜基模解耦 | 零 |
| 合成/评分/成本链 | 不感知基模 | 零 |
| 依赖 | ComfyUI_InstantID 节点包 + onnxruntime + antelopev2；PuLID 需 ComfyUI_PuLID_Dialect | 节点包安装 + 重启验证 |

## 五、分阶段落地路线（建议）

- **阶段 1（预验，半天）**：落 DreamShaper XL + InstantID 节点包；零 LoRA 单独评测（对齐 FaceID PlusV2 先例：先测纯基模 + InstantID 的 4 种子 mean/min）。达标线：单独 mean >= 0.80（SD15 时代 PLUS FACE 单独 0.67/FaceID 单独 0.7926 为参照）。
- **阶段 2（重训，一天）**：n1 SDXL LoRA 重训（v2 数据集，dim32 起步）+ combo 扫描（LoRA x InstantID 权重网格，对齐 M3 二轮方法论）。
- **阶段 3（决策）**：mean >= 0.85 且 min 不低于 FaceID 组合 0.8036 方触发生产切换评审；否则归档预研结论，维持现役双档位。
- **回退保障**：现役 SD15 全链零改动保留（checkpoint/LoRA/双档位 adapter 均在位），迁移全程可一键回退。

## 六、风险与开放问题

| 风险 | 等级 | 缓解 |
| ---- | ---- | ---- |
| SDXL LoRA 重训后 min 不升反降（v2m777 泛化教训迁移风险） | 中 | 阶段 2 严格双口径判定，不达标不切换 |
| Mac 1024 生成耗时放大拖慢夜批 | 低 | 产能预算已容纳；必要时静态镜切 n1 |
| InstantID 对古风插画风格的照片感偏移 | 中 | prompt 锚定 + run_style_keeper 风格守护复用 |
| DreamShaper XL 下载通道不稳 | 低 | hf-mirror/civitai 双通道 |

## 七、结论

**可行**：内存/算力充裕、评测协议零变更复用、回退保障完备；核心成本为 SDXL LoRA 全量重训一轮与 1024 生成耗时放大。建议按阶段 1-3 推进，阶段 1 纯基模预验为第一道门槛。

## 八、阶段 1 执行回执（2026-10-05，40 轮落地）

**前置核验（全绿）**：ComfyUI@41888 在线；`ComfyUI_InstantID` 节点已注册（`/object_info/InstantIDModelLoader` 可达，**无需重启**）；`checkpoints/DreamShaperXL_Lightning.safetensors` 6.5G 完整；`instantid/ip-adapter.bin` 1.6G；`controlnet/instantid/controlnet.safetensors` 2.3G；`clip_vision/CLIP-ViT-H-14…` 2.4G；`insightface/models/antelopev2` 在位；onnxruntime 1.30.0；磁盘余量 707G。

**执行**：`scripts/run_sdxl_instantid_preval.py`（纯基模零 LoRA + InstantID weight 0.8，Lightning 档 steps=8/cfg=1.8/euler/sgm_uniform @1024²，评分协议与 SD15 完全一致：4 漂移种子 insightface 512d 余弦 vs 设定图本体）。

| 口径 | mean | min | max | 单张耗时 |
| ---- | ---- | --- | --- | -------- |
| **SDXL 零 LoRA + InstantID（本轮回执）** | **0.8446** | **0.8321** | 0.859 | 20.1s |
| SD15 v2 combo 生产（现役） | 0.8672 | 0.7846 | — | 27.4s |
| SD15 FaceID 单独 | 0.7926 | — | — | — |
| SD15 PLUS FACE 单独 | 0.67 | — | — | — |

逐种子：777→0.859 / 888→0.8455 / 999→0.8416 / 1111→0.8321。

**判定**：
- 门槛 **mean ≥ 0.80 → PASS（0.8446，超出 +4.46pp）**。
- **关键发现（超预期）**：零 LoRA、零 IPAdapter、零 combo 的纯 SDXL+InstantID 已逼近现役 SD15 全组合式（mean 差仅 -2.26pp），而 **min 0.8321 反超现役 0.7846（+4.75pp）**——直接命中本项目长期短板（最差帧稳定度）。
- 耗时 20.1s/张 反而**快于**现役 SD15 1024 口径 27.4s（Lightning 8 步蒸馏红利），产能无恶化。

**结论**：**阶段 1 PASS，阶段 2（n1 SDXL LoRA 重训 + combo 扫描）解锁**。按阶段 3 决策线（mean ≥ 0.85 且 min ≥ 0.8036 方触发生产切换评审），当前已满足 min 条，仅差 mean 2.3pp——叠加 SDXL LoRA 后突破 0.85 概率高。留证：[tc-sdxl-instantid-preval-20261005.json](attachments/G5-20261005/tc-sdxl-instantid-preval-20261005.json)。
