## 一、体系总览

### 1.1 整体架构定位

YYC³ 三大仓库形成 **「底座层 → 编排层 → 能力组件层」** 三级技术中台，向下统一纳管硬件算力与存储资源，向上支撑 AI 漫剧全链路业务生产，实现「硬件资源池化、AI 能力标准化、生产流程智能化、业务资产沉淀化」的完整闭环。

三大仓库并非独立系统，而是分层解耦、能力递进的有机整体：

| 层级 | 系统 | 核心定位 |
| ---- | ---- | -------- |
| 底座层 | 0379-World 统一 AI 网关 | 所有能力的入口与调度中枢 |
| 编排层 | AI Agent Archive 多智能体体系 | 生产流程的智能调度大脑 |
| 能力组件层 | MiniMax-H3 本地视频生产线 | 视频动态化的核心执行单元 |
| 业务层 | AI 漫剧全链路生产系统 | 技术体系的业务落地载体 |

### 1.2 四层架构全景

│  业务层：AI漫剧全链路生产系统                                  │

## 二、底座层：0379-World 统一 AI 网关

### 2.1 项目核心定位

YYC³ 0379-World 是生产级全链路 AI 模型网关与智能协同中台，基于 FastAPI 构建，提供 OpenAI 兼容的统一 API 接口，核心解决四大问题：

| 问题 | 网关解决方案 |
| ---- | ------------ |
| 多模型分散接入 | 统一 OpenAI 兼容接口，LLM / Embedding / Rerank / ASR 一站式接入 |
| 算力调度不均 | 自适应路由引擎（EWMA 延迟 + 错误率 + 负载），自动调度双节点 |
| 能力标准不统一 | 标准 MCP 工具生态，统一注册、鉴权、调度 |
| 可观测性缺失 | Prometheus + Grafana 全链路可观测，请求追踪、延迟统计、健康检查 |

### 2.2 与现有硬件的原生适配度

| 硬件 | 系统定位 | 对应部署方案 | 可复用资产价值 |
| ---- | -------- | ------------ | -------------- |
| NVIDIA DGX Spark GB10 ×2 | DGX 双机推理池（TP=2） | `deploy/dgx/` 下全套配置、双机负载均衡脚本 | 直接复用双 DGX 推理部署方案，原生支持 DeepSeek 等大模型张量并行，开箱即用 |
| NAS（RAID1/RAID6） | NAS 网关层 + 共享存储底座 | `deploy/nas/` 下 docker-compose.nas.yml、NAS 网关部署脚本 | 统一存储入口，模型、数据、资产全部存 NAS，多节点共享访问 |
| Mac M4 128G | 调度控制端 + 边缘接入节点 | 网关控制面、Agent 编排服务 | 利用 Media Engine 做视频后处理，算力专责专用 |

### 2.3 向上衔接能力（对编排层）

- **统一接口**：提供标准 OpenAI 兼容 API，Agent Archive 无需感知底层模型分布，仅需配置一个 `base_url` 即可调用所有能力
- **MCP 工具生态**：内置 14 个标准 MCP 工具，可直接注册到 Agent Archive 的 mcp-runtime，实现工具能力共享
- **可观测输出**：Prometheus 指标 + 结构化日志，同步给 Agent 体系做生产监控与效能分析

### 2.4 向下纳管能力（对硬件与组件）

- **算力纳管**：通过 `OPENAI_COMPATIBLE_UPSTREAMS` 环境变量，纳管双 DGX 上的所有模型服务，支持自适应路由、熔断降级、负载均衡
- **组件纳管**：MiniMax-H3 视频能力作为第五类能力（video）接入上游池，统一调度、统一鉴权、统一监控
- **存储纳管**：所有模型文件、资产数据、项目文件统一挂载 NAS，按标准路径访问，避免数据冗余

### 2.5 存储与数据衔接规范

**NAS 统一挂载**：网关服务、DGX 推理服务、Agent 服务、漫剧业务服务统一挂载 `/mnt/nas/` 路径，数据分层存储：

| 存储位置 | 数据内容 |
| -------- | -------- |
| PostgreSQL（NAS RAID1） | 网关配置、用户权限、知识库元数据、调用日志 |
| pgvector（NAS RAID6） | 向量索引、素材特征、剧本语义向量 |
| NAS 文件存储（RAID6） | 大模型文件、LoRA、素材、成片、项目工程文件 |

**缓存复用**：网关内置 Redis 多级缓存，常用剧本分镜、提示词、Embedding 结果自动缓存，重复请求命中率提升 60% 以上，减少 DGX 无效算力消耗。

### 2.6 核心可复用资产

| 资产 | 说明 |
| ---- | ---- |
| `deploy/dgx/` | 双 DGX 推理池全套部署配置，4 套 docker-compose 模板 |
| `deploy/nas/` | NAS 网关部署方案，docker-compose.nas.yml |
| 自适应路由引擎 | EWMA 延迟 + 错误率 + 负载动态权重调度 |
| 上游池熔断机制 | 连续 3 败摘除 30s 半开，自动降级与恢复 |

### 2.7 进阶优化方向

- **模型分层调度**：简单剧本拆解用小模型，复杂分镜/创意用大模型，通过网关自动路由，进一步降低算力成本
- **批量任务优化**：漫剧批量生图任务通过网关批量接口合并请求，提升 DGX 显存利用率，单批次吞吐量提升 30%
- **数据闭环增强**：网关采集的生产数据同步给预见·先知 Agent 做分析，自动优化后续生产流程，形成完整智能闭环

## 三、编排层：AI Agent Archive 多智能体中枢

### 3.1 核心定位与价值

作为生产体系的智能大脑，将传统的固定流水线升级为多智能体自主协同生产，覆盖创意、生产、质检、运营、优化全环节，实现生产流程从「人工配流程」到「Agent 自主排产、自主优化」的升级。

### 3.2 与 0379-World 的衔接方式

- **模型接口打通**：Agent Runtime 配置上游模型地址为 0379-World 网关地址，统一 API Key 鉴权，所有智能体共享一套模型入口
- **MCP 能力互通**：网关内置的 MCP 工具注册到 Agent 的 mcp-runtime，漫剧自定义生产工具（生图、生视频、合成）反向注册到网关，统一管理
- **数据互通**：网关的调用日志、性能指标同步到 Agent 的可观测体系，统一监控生产全链路

### 3.3 与 MiniMax-H3 的协同逻辑

| Agent | 协同动作 |
| ----- | -------- |
| 创想·灵韵 | 作为视频生产执行者，通过网关调用 MiniMax-H3 能力，完成漫剧动态化、口型同步任务 |
| 智云·守护 | 调用 MiniMax-H3 的口型评分能力（SyncNet），完成视频质量自动质检 |
| 元启·天枢 | 根据任务优先级，调度 Mac 版（快速预览）或 DGX 版（高质量批量）生成资源 |

### 3.4 核心可复用资产

- 8 大智能体原生框架，支持场景化定制 prompt
- Skill 统一注册中心 + 沙箱执行环境，生产能力资产化
- Conductor 协同编排引擎 + Orchestrator 智能调度器
- 600+ 技能资产、200+ 插件，可直接复用通用能力

> 8 大 Agent 漫剧场景分工矩阵与全链路编排流程，详见 [YYC3-03-AI漫剧智能体编排方案.md](YYC3-03-AI漫剧智能体编排方案.md)。

## 四、能力组件层：MiniMax-H3 视频生产线

### 4.1 核心定位与价值

作为漫剧生产的视频动态化核心执行单元，提供本地化的图生视频、数字人口型同步能力，配套完整的「批量生成 → 自动评分 → 分析优化 → Seed 迭代」闭环，解决漫剧生产中「动态化效果差、口型对不上、批量质量不稳定」的痛点。

### 4.2 双硬件部署方案（分工协同）

采用「Mac 快速预览 + DGX 高质量批量」双部署模式，算力专责专用：

| 部署位置 | 模型版本 | 核心用途 | 优势 |
| -------- | -------- | -------- | ---- |
| Mac M4 128G（MPS 加速） | Pruned 剪枝版 | 单镜头快速预览、Seed 试错、轻量视频生成 | 响应快、成本低，白天快速迭代创意 |
| 双 DGX GB10（CUDA 加速） | NF4 原版 | 批量高质量渲染、正式成片生成、大批量生产 | 画质高、速度快，夜间批量生产 |

### 4.3 接入 0379-World 的方式

1. **封装标准 API**：将 MiniMax-H3 的生成、评分能力封装为 OpenAI 兼容的异步任务接口
2. **接入上游池**：通过 `OPENAI_COMPATIBLE_UPSTREAMS` 配置到网关，作为 video 能力节点，纳入统一调度
3. **配置路由规则**：低优先级预览请求路由到 Mac 节点，高优先级批量任务路由到 DGX 节点
4. **状态回调**：异步任务状态通过 SSE 实时回传给 Agent 编排层，同步生产进度

### 4.4 漫剧业务场景应用

- **关键帧动态化**：静态分镜图生成带微表情、环境流动、镜头运镜的动态视频片段
- **口型自动同步**：匹配 TTS 配音，自动生成对口型的角色画面，SyncNet 自动评分校验
- **批量迭代优化**：夜间批量生成多版本，自动评分筛选最优 Seed，沉淀到资产库
- **数字人出镜**：支持真人数字人讲解、角色真人化等拓展玩法

### 4.5 核心可复用资产

- `scripts/`：全套生成脚本，支持单次、批量、闭环流水线
- `models/syncnet/`：双后端口型评分模型，自动质量校验
- `docs/`：完整的部署、排障、优化指南，含 DGX 迁移方案
- 闭环流水线：生成 → 打分 → 分析 → 更新 Seed，质量持续自优化

## 五、关键衔接断点与闭环解决方案

### 5.1 接口鉴权断点：0379-World ↔ Agent Archive

**断点问题**

- 0379-World 采用 X-API-Key + JWT 双鉴权体系，支持 IP 限流、权限分级
- Agent Archive 原生为内部 Skill Gateway 鉴权，两套体系密钥、权限、限流规则不互通
- MCP 工具调用跨系统鉴权失败，工具能力无法共享

**闭环方案**

1. **统一鉴权入口**：所有 Agent 的模型请求、工具请求全部走 0379-World 网关，Agent 侧仅配置一个网关 API Key，取消本地模型密钥配置
2. **权限映射规则**：网关侧按 Agent 角色分配模型权限：

| Agent | 开放权限 |
| ----- | -------- |
| 语枢·万物 | 仅开放 LLM、Embedding、RAG 权限 |
| 创想·灵韵 | 开放文生图、视频生成、素材库权限 |
| 元启·天枢 | 开放路由监控、算力调度权限 |

1. **MCP 代理模式**：Agent 侧的 MCP Runtime 不直接连接外部工具，全部通过网关 `/v1/mcp/*` 代理调用，统一鉴权、统一审计、统一限流

### 5.2 异步任务断点：MiniMax-H3 ↔ 0379-World

**断点问题**

- 0379-World 原生接口以同步 Chat、Embedding 为主，无长时异步任务标准
- MiniMax-H3 视频生成为分钟级长任务，原生脚本为本地同步调用，无法纳入网关统一调度
- Agent 下发任务后无法追踪进度、失败原因、质检结果，流程中断

**闭环方案**

1. **网关扩展异步任务标准接口**：新增 `/v1/video/generations` 异步接口，遵循「提交任务 → 状态查询 → SSE 回调」三段式协议：
   - `POST` 提交任务，返回 task_id
   - `GET` 查询任务状态（pending / running / success / failed）
   - SSE 实时推送进度、帧数、耗时、中间状态
2. **MiniMax-H3 服务化改造**：
   - 封装 batch_ref2va_nf4.py 为标准 API 服务，部署于 Mac 和 DGX 双节点
   - 接入网关上游池，标记为 video-minimax-h3 能力节点
   - 支持 preview（Mac 剪枝版）和 quality（DGX 完整版）两种路由标签
3. **状态机同步**：每个任务输出标准化状态 JSON，包含进度、耗时、显存峰值、质检分数，通过 WebSocket 实时同步给 Agent 编排层，支撑全流程可视化

### 5.3 数据路径断点：跨平台 NAS 路径不一致

**断点问题**

- Mac 端通过 SMB 挂载 NAS，路径为 `/Volumes/nas/`
- DGX 端通过 NFS 挂载 NAS，路径为 `/mnt/nas/`
- 生成任务中写入的路径在跨节点读取时失败，是本地部署最高发的故障点

**闭环方案**

1. **统一标准路径**：所有节点强制创建软链接，统一根路径为 `/mnt/nas/`：
   - Mac 端执行：`ln -s /Volumes/nas /mnt/nas`
   - DGX 端保持原生 NFS 挂载路径 `/mnt/nas/`
   - 网关、Agent、业务系统全部使用标准路径，无感知底层差异
2. **网关侧路径映射**：网关配置路径转换中间件，不同节点上报的路径自动归一化，写入数据库的全部为标准路径
3. **项目目录规范**：所有项目按 `/mnt/nas/projects/{project_id}/{step}/` 统一结构存储，生成结果直接写入对应目录，跨节点直接读取

### 5.4 流程状态断点：Agent 编排 ↔ 生产执行

**断点问题**

- Agent 下发任务后进入黑盒，无法感知中间环节的失败、重试、质检结果
- 生产异常无法自动触发回退、重跑、人工介入，流程断链
- 生产数据无法沉淀为资产，不能反哺优化

**闭环方案**

1. **全链路状态埋点**：剧本拆解、分镜生成、生图、视频生成、质检、合成 6 个环节，每个节点输出标准化状态事件，包含：
   - 任务 ID、环节、状态、耗时
   - 输入输出文件路径、参数、Seed
   - 错误码、错误信息、重试次数
2. **异常自动处理机制**：

| 错误级别 | 示例 | 处理策略 |
| -------- | ---- | -------- |
| 轻度错误 | 单帧生成失败 | 自动重试 2 次，重试失败标记告警 |
| 中度错误 | 节点宕机 | 自动切换到备用 DGX 节点，任务断点续传 |
| 重度错误 | 内容违规 | 直接终止，推送人工审核 |

1. **数据自动沉淀**：合格任务的参数、Seed、效果评分自动写入 NAS 资产库，注册为标准 Skill，后续同类任务优先推荐

### 6.3 Mac 端统一 NAS 路径初始化脚本

`scripts/init_nas_path.sh`，一键解决路径不一致问题：

```bash
#!/bin/bash
# 统一NAS路径为/mnt/nas

if [ ! -d "/mnt" ]; then
    sudo mkdir -p /mnt
fi

if [ -d "/Volumes/nas" ] && [ ! -L "/mnt/nas" ]; then
    sudo ln -s /Volumes/nas /mnt/nas
    echo "NAS路径已统一: /mnt/nas"
else
    echo "NAS路径已存在或未挂载"
fi

# 验证
ls /mnt/nas/models/ && echo "路径验证通过"
```

## 八、全链路运维与高可用保障

### 8.1 双 DGX 算力高可用

| 机制 | 说明 |
| ---- | ---- |
| 健康检查 | 网关每 10 秒探测双节点健康状态，连续 3 次失败自动摘除节点 |
| 熔断降级 | 单节点错误率超过 15% 自动熔断 30 秒，半开验证恢复后重新接入 |
| 流量灰度 | 新增模型、新版本先切 10% 流量到单节点，验证稳定后全量放开 |
| 故障切换 | 单台 DGX 故障时，任务自动迁移到另一台，产能下降但生产不中断 |

### 8.2 数据可靠性保障

| 机制 | 说明 |
| ---- | ---- |
| 存储冗余 | 核心数据 RAID1 镜像，资源数据 RAID6 双校验，单盘/双盘故障零丢失 |
| 定期备份 | PostgreSQL 数据库每日全量备份到 NAS 灾备区，保留 30 天版本 |
| 项目快照 | 关键项目节点自动生成快照，支持一键回退到任意版本 |
| 异地备份 | 核心资产定期冷备份到外置硬盘，防范 NAS 整机故障 |

### 8.3 全链路监控大盘

Grafana 统一监控四大维度，一屏掌控全生产状态：

| 维度 | 监控指标 |
| ---- | -------- |
| 算力维度 | 双 DGX 显存使用率、GPU 利用率、温度、功耗 |
| 任务维度 | 待办任务数、执行中任务数、成功率、平均耗时 |
| 质量维度 | 人物一致性达标率、口型同步平均分、成片合格率 |
| 成本维度 | 单日算力消耗、单集平均成本、资产复用率 |

### 8.4 故障排查体系

- **日志聚合**：所有节点日志统一收集到 NAS 日志目录，按天归档
- **告警通知**：关键故障（节点宕机、任务失败率超阈值）推送内网告警
- **断点续传**：所有任务支持断点续传，中断后无需从头开始
- **排障脚本**：内置 `doctor.sh` 一键排查网络、挂载、模型、服务状态

## 九、核心价值总结

### 9.1 硬件效率最大化

- **算力专责专用**：重算力任务跑 DGX，调度与合成跑 Mac，充分发挥各自硬件优势

- **存储统一共享**：NAS 双 RAID 架构，所有节点共享数据，无冗余，高可靠

### 9.2 技术体系标准化

- **接口统一**：所有 AI 能力通过网关标准化，上层业务无需感知底层细节
- **资产标准化**：所有生产能力、素材、模板封装为标准 Skill，可复用、可版本、可管理
- **流程标准化**：全链路遵循统一的生产规范与质量标准，产出稳定可控

### 9.3 生产能力工业化

- **多智能体协同**：8 大 Agent 分工协作，70% 以上流程自动化，人力成本大幅降低
- **批量产能支撑**：双 DGX + 夜间批量模式，日均产出 20-30 集，支持多项目同时连载
- **质量闭环优化**：自动质检 + 迭代机制，成片合格率从 70% 提升至 90%+

### 9.4 资产沉淀持续化

模型、素材、模板、Seed、脚本持续沉淀，越用效率越高，形成团队不可替代的数据资产护城河。
