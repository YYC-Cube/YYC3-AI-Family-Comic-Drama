## 一、硬件资源定位与分工总览

### 1.1 硬件角色与核心价值

| 设备 | 核心配置 | 系统定位 | 核心优势 |
| ---- | -------- | -------- | -------- |
| NVIDIA DGX Spark GB10 ×2 | Blackwell 架构 GPU、大显存高带宽 | 主力算力集群 | 原生 AI 推理/训练加速，承担所有 GPU 密集型生成任务，双节点负载均衡 + 故障互备 |
| Mac M4（32核/128GB 统一内存） | 苹果硅 CPU + Media Engine 硬件编解码 | 调度管控 + 后期合成节点 | 大统一内存 + 硬件编解码，负责前端交互、任务编排、视频硬件加速合成，能效比远高于纯 CPU 方案 |
| NAS（RAID1 + RAID6 双架构） | 双冗余磁盘阵列、大容量共享存储 | 统一数据底座 | 所有资产、模型、项目、成品集中存储，多节点共享访问，避免数据冗余 |

### 1.2 核心设计原则

| 原则 | 说明 |
| ---- | ---- |
| 算力专责专用 | 重 GPU 负载全部下沉 DGX 集群，Mac 发挥端侧交互与视频编码优势，不浪费高端算力在非 AI 任务上 |
| 存储统一共享 | 所有资源数据存 NAS，多节点统一挂载路径，任务调度无路径差异 |
| 流水线并行 | 各节点分工协作，分镜→生图→生视频→合成全链路流水线化，硬件利用率最大化 |
| 全链路冗余 | 双 DGX 算力互备 + 双 RAID 存储冗余，无单点故障，支撑 7×24 小时生产 |

## 二、定制化三层部署架构

### 2.1 架构总览

```
┌─────────────────────────────────────────────────────────┐
│  接入&调度层（Mac M4）                                   │
│  前端工作台 | 后端编排 | 任务调度 | 视频合成 | 轻量推理  │
├─────────────────────────────────────────────────────────┤
│  算力层（DGX Spark GB10 ×2 负载均衡集群）                │
│  LLM推理 | 文生图 | 图生视频 | LoRA训练 | 一致性校验     │
├─────────────────────────────────────────────────────────┤
│  存储层（NAS 双RAID）                                    │
│  核心数据区(RAID1) | 大容量资源区(RAID6)                 │
└─────────────────────────────────────────────────────────┘
```

### 2.2 各层详细部署

#### 接入&调度层（Mac M4）

作为本地生产的操作中枢，承担非 GPU 密集型的全部工作：

| 职能 | 说明 |
| ---- | ---- |
| 前端交互 | React 工作台本地部署，浏览器访问即可完成全流程操作 |
| 任务编排 | FastAPI + Celery + Redis，实现 DAG 工作流解析、任务分发、状态追踪 |
| 视频后期 | FFmpeg（启用 VideoToolbox 硬件加速）+ MoviePy，负责片段拼接、转场、字幕渲染、成片导出 |
| 轻量推理 | 量化版 TTS、口型同步预处理、基础画质检测 |
| 管控运维 | 算力监控、项目管理、数据看板、权限配置 |

#### 算力层（双 DGX GB10 集群）

作为 AI 生成的核心引擎，全部模型服务化部署，由 Mac 调度层统一调用：

- **负载均衡架构**：两台 DGX 通过 Nginx 反向代理实现任务自动分发，单台故障时秒级切换，产能下降但生产不中断

**核心服务模块**：

| 服务 | 说明 |
| ---- | ---- |
| LLM 推理服务 | vLLM 部署 72B 级大模型，负责剧本拆解、分镜生成、提示词工程，吞吐量是原生部署的 4 倍 |
| 文生图服务 | ComfyUI API 化部署，加载 SDXL/Flux + LoRA + ControlNet，批量生成关键帧 |
| 图生视频服务 | AnimateDiff / Seedance 服务化，静态帧转动态镜头 |
| 模型训练服务 | 角色/场景 LoRA 微调、人脸特征编码器训练 |
| 一致性校验服务 | 512 维人脸特征提取、跨镜头身份比对、智能画质质检 |

#### 存储层（NAS 双 RAID 架构）

按数据重要性与容量需求拆分存储，兼顾可靠性与成本：

| 分区 | 特性 |
| ---- | ---- |
| RAID1（镜像阵列） | 存储容量小、可靠性要求极高的核心数据，双盘镜像，单盘故障零影响 |
| RAID6（双校验阵列） | 存储大容量资源文件，支持 2 块盘同时故障，容量利用率高，适合大文件顺序读写 |

## 三、全链路任务路由与算力分配

对应 AI 漫剧六大生产环节，精准匹配硬件能力，实现最优效率。

### 3.1 剧本语义结构化 → Mac 调度 + DGX 推理

1. Mac 接收剧本输入，组装请求转发至 DGX 集群
2. DGX 运行大语言模型，完成文本清洗、剧情拆解、分集规划、分镜生成
3. 结构化分镜结果回传 Mac，自动存入 NAS 对应项目目录

### 3.2 人物一致性管控 → DGX 全流程承担

1. 角色特征提取、LoRA 加载、生成中身份锚定、生成后偏差校验，全流程在 DGX 侧完成
2. 人物特征向量存入 NAS 资产库，全项目复用
3. 偏差超阈值时自动触发重绘，无需人工干预

### 3.3 分镜视觉生成 → DGX 集群批量并行

1. Mac 将整集分镜批量提交到 DGX 任务队列
2. 两台 DGX 负载均衡，并行生成关键帧，单集 15 个镜头可在 2-3 分钟内全部完成
3. 生成的高清原图直接写入 NAS 项目目录，Mac 端实时读取预览

### 3.4 动态化与多模态同步 → DGX + Mac 分工协作

1. **图生视频**：DGX 运行生成模型，输出带动态效果的视频片段
2. **语音生成**：普通配音用 Mac 本地量化 TTS，高要求情感配音调度 DGX 算力
3. **口型对齐**：预处理在 Mac 完成，精细对齐调度 DGX 加速
4. **时间轴校准**：Mac 本地完成，毫秒级精度，速度远高于 GPU 方案

### 3.5 后期合成与成片输出 → Mac 硬件加速

1. 片段拼接、转场特效、字幕渲染、音画合成全部在 Mac 端完成
2. 启用苹果 Media Engine 硬件编码，1080P 视频导出速度可达 300fps 以上，是纯 CPU 的 5-8 倍
3. 最终成片自动归档到 NAS 成品区，不占用本地存储

### 3.6 数据反馈与迭代 → Mac 调度 + DGX 训练

1. Mac 采集运营数据，生成内容效果分析报告
2. 需要模型微调时，自动调度 DGX 空闲算力完成 LoRA 训练
3. 优质资产自动沉淀到 NAS 对应库，持续提升后续生产效率

## 四、NAS 存储规划与目录结构

### 4.1 RAID 分区与存储内容

| 分区 | RAID 级别 | 存储内容 | 设计逻辑 |
| ---- | --------- | -------- | -------- |
| 核心数据区 | RAID1 | 项目数据库、系统配置、核心 IP 的 LoRA 模型、权限数据 | 容量小、价值高，最高可靠性保障 |
| 模型资源区 | RAID6 | 基础大模型、ControlNet、图生视频模型、TTS 模型 | 文件大、顺序读写为主，2 盘容错 |
| 资产素材区 | RAID6 | 角色素材、场景素材、音效、字体、分镜模板 | 大容量共享资源，多项目复用 |
| 项目工作区 | RAID6 | 所有项目的工程文件、中间产物、成片源文件 | 高并发读写，支撑多节点同时操作 |
| 成品归档区 | RAID6 | 最终成片、封面图、发布素材 | 长期归档，大容量存储 |
| 灾备备份区 | RAID1 | 核心数据库每日备份、关键项目快照 | 灾备专用，物理隔离 |

### 4.2 统一挂载目录结构

所有节点统一挂载路径为 `/mnt/nas/`，彻底避免多节点路径不一致导致的任务失败。

```
/mnt/nas/
├── core/                # RAID1 核心数据区
│   ├── database/        # PostgreSQL数据文件
│   ├── config/          # 系统配置文件
│   └── lora-core/       # 核心IP专属LoRA
├── models/              # RAID6 模型资源区
│   ├── llm/
│   ├── sd/
│   ├── controlnet/
│   ├── animatediff/
│   └── tts/
├── assets/              # RAID6 资产素材库
│   ├── characters/
│   ├── scenes/
│   ├── templates/
│   ├── audio/
│   └── fonts/
├── projects/            # RAID6 项目工作区
│   ├── project-001/
│   │   ├── script/      # 剧本文件
│   │   ├── storyboard/  # 分镜文件
│   │   ├── images/      # 生成关键帧
│   │   ├── clips/       # 视频片段
│   │   └── output/      # 成片导出
│   └── project-002/
├── archive/             # RAID6 成品归档
│   └── 2026-09/
└── backup/              # RAID1 灾备备份
    ├── db-daily/
    └── project-snapshots/
```

### 4.3 挂载方式

| 节点 | 协议 | 说明 |
| ---- | ---- | ---- |
| Mac 端 | SMB | 支持访达直接访问，配置自动挂载，开机即可用；通过软链接统一为 `/mnt/nas/`（见总纲 5.3 节） |
| DGX 端 | NFS | Linux 原生支持，高并发读写稳定，写入性能优于 SMB |

## 五、分步部署实施方案

### 5.1 第一步：NAS 存储初始化

1. 创建 RAID1 与 RAID6 阵列，按规划划分 6 个分区
2. 配置共享账号与权限，区分读写账号与只读账号
3. 初始化统一目录结构
4. 导入基础模型、通用素材到对应目录

### 5.2 第二步：DGX 算力集群部署

1. 两台 DGX 配置 Docker + NVIDIA Container Toolkit，统一运行环境
2. 分模块部署模型服务：
   - **LLM 服务**：vLLM 启动，暴露 OpenAI 兼容 API
   - **文生图服务**：ComfyUI 后端 API 模式，预加载基础模型与 ControlNet
   - **图生视频服务**：AnimateDiff 服务化部署
   - **一致性校验服务**：人脸特征提取 API
3. 部署 Nginx 反向代理，实现两台 DGX 负载均衡与健康检查
4. 挂载 NAS 共享目录，路径统一为 `/mnt/nas/`

### 5.3 第三步：Mac 调度节点部署

1. 安装基础环境：Homebrew、Python 3.11、Node.js 20、FFmpeg（带 VideoToolbox 编译）
2. 部署后端服务：FastAPI + Celery + Redis，配置 DGX 集群 API 地址
3. 部署前端工作台：构建 React 项目，本地 Nginx 托管
4. 挂载 NAS 共享目录，路径与 DGX 完全一致
5. 配置任务路由规则，实现不同任务自动分发到对应算力节点

### 5.4 第四步：全链路联调验证

| 验证项 | 内容 |
| ------ | ---- |
| 单任务全流程测试 | 剧本输入 → 分镜 → 生图 → 生视频 → 合成 → 导出 |
| 双节点故障测试 | 断开单台 DGX，验证任务自动切换 |
| 存储一致性测试 | 多节点读写同一文件，验证数据同步 |
| 性能压测 | 批量任务吞吐量、单集生成耗时、硬件利用率 |

## 六、生产优化与昼夜错峰策略

### 6.1 核心优化点

| 优化项 | 要点 |
| ------ | ---- |
| DGX 算力优化 | 启用 FP8 精度 + TensorRT 加速，文生图速度提升 2-3 倍；vLLM 连续批处理，LLM 吞吐量提升 4 倍；同类任务批量提交，最大化 GPU 利用率 |
| Mac 视频优化 | FFmpeg 启用 h264_videotoolbox 硬件编码，2 分钟漫剧导出仅需 10-15 秒 |
| 网络优化 | 万兆有线连接全设备，启用 9000 字节巨帧，大文件传输速度 ≥ 1000MB/s |
| 调度优化 | 流水线并行生产，同一项目的生图、生视频、合成重叠执行，整体周期缩短 40% |

### 6.2 昼夜错峰生产策略

结合硬件特性最大化产能：

| 时段 | 硬件 | 任务类型 | 说明 |
| ---- | ---- | -------- | ---- |
| 白天 08:00-22:00 | Mac M4 + 单 DGX | 创意试错、单镜预览、分镜调整、剪辑合成 | 低延迟快速迭代，保障创作效率 |
| 夜间 22:00-08:00 | 双 DGX 满负载 | 批量生图、批量视频渲染、LoRA 训练 | 错峰跑满算力，次日直接取用结果 |

配置 `nightly_run.sh` 定时触发批量任务，次日清晨自动生成质检报告，人工仅需审核。

## 七、产能估算与可靠性保障

### 7.1 产能估算（单集 2 分钟标准漫剧）

| 指标 | 数值 |
| ---- | ---- |
| 单集全流程耗时 | 12-18 分钟（含剧本处理、15 个镜头生成、动态化、合成导出） |
| 日常批量产能 | 日均产出 20-30 集，支持 3-5 个项目同时连载 |
| 峰值素材产能 | 单日可生成 1200+ 关键帧，支撑 60+ 集的素材量 |

### 7.2 可靠性保障

| 保障项 | 说明 |
| ------ | ---- |
| 算力冗余 | 双 DGX 互备，单台故障不中断生产，仅产能下降 50% |
| 存储冗余 | RAID1/RAID6 双冗余，单盘/双盘故障零数据丢失 |
| 数据备份 | 核心数据库每日自动备份，关键项目支持快照回溯 |
| 离线运行 | 全系统本地化部署，无外网环境可正常生产，数据零外泄 |
