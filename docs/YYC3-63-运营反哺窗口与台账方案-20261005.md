# TC-G5-001/004 运营反哺前置方案（曝光窗口 + 伯乐台账）

## 一、定位与目标

G5 六用例中 002/003/005 已 PASS（2026-10-05 收割），**001（完播率对比）与 004（排期采纳率）是仅剩两项**，均属「真实运营数据依赖」——本方案给出可执行的窗口排期、采集口径与台账契约，使两项用例从 BLOCKED 转为「待窗口、机制就绪」。

## 二、TC-G5-001 完播率对比（≥5 个百分点）

### 2.1 两期窗口设计（对齐手册口径「反哺前后对比」）

| 期 | 窗口 | 内容 | 采集口径 |
| -- | ---- | ---- | ---- |
| **基线期 P0** | 建议连续 7 天 | SD15 时代产线旧成片（或未启用运营建议的新片）对照 | 每集 ≥30 有效会话 |
| **反哺期 P1** | P0 后连续 7 天 | 经「预见·先知 + 知遇·伯乐」反哺建议调整后新片（节奏/钩子/封面/标题） | 同口径 |

- **有效会话**：播放 ≥3s 且非自刷（IP+UA 去重）；每集不足 30 会话则该集不计入（窗口顺延）
- **完播率**：`完整观看时长 / 成片时长` 平台口径；无平台字段时用「观看 ≥90% 时长会话占比」替代并留证口径说明
- **判定**：`mean(P1 完播率) − mean(P0 完播率) ≥ 5pp` → PASS（逐集留证 + 均值双报）

### 2.2 内容池（已就绪）

- 六集 SDXL 成片（sdxl-prod-001~006，18/18 首绘直通产线）：本地 `~/YYC-Cube/YYC3-assets/projects/` + n1 `~/yyc3-archive/projects/`（2026-10-05 归档，MD5 核对）
- P0/P1 分组建议：P0 用 ep01–03（旧三章），P1 用 ep04–06（新三章且含运营建议注入位）——**同产线不同内容代次**，避免「模型升级」与「运营反哺」混杂归因；如需更强对照可同集双版本（有无反哺建议）

### 2.3 采集留证契约（docs/ops/g5-ops-ledger.json → completion 字段）

```json
{"completion": {
  "phase": "P0|P1",
  "episode_id": "sdxl-prod-001",
  "platform": "douyin|wechat|bilibili|local-preview",
  "window": {"start": "YYYY-MM-DD", "end": "YYYY-MM-DD"},
  "sessions_valid": 32,
  "completion_rate_mean": 0.412,
  "metric_note": "观看≥90%时长会话占比（平台无完播字段替代口径）"
}}
```

## 三、TC-G5-004 伯乐排期采纳率（≥60%，≥4 周期）

### 3.1 周期与台账设计

- **周期**：以「夜批窗口」为周期单位（日粒度），**≥4 个周期**起判
- **建议来源**：知遇·伯乐（zhiyu_bole）排期建议（题材/顺序/发布时点）；样片阶段可由 run_batch_shots 的 style/prompt 定制建议占位，如实标注 `source: "manual|bole-agent"`
- **采纳判定**：当期实际排期与建议一致（集序/风格档/时点三项中 ≥2 项一致记采纳）
- **判定**：`采纳数 / 建议数 ≥ 60%` 且周期数 ≥4 → PASS

### 3.2 台账契约（同账本 → scheduling 字段）

```json
{"scheduling": {
  "cycle_id": "2026-10-06-night",
  "suggestions": [{"episode_id": "sdxl-prod-004", "style": "夜雨悬疑", "slot": "19:00-21:00", "order": 1}],
  "actual":     [{"episode_id": "sdxl-prod-004", "style": "夜雨悬疑", "slot": "19:30", "order": 1}],
  "adopted": true,
  "decided_by": "user",
  "note": "时点后移 30min，集序/风格一致 → 记采纳（2/3 一致）"
}}
```

## 四、判定器与门禁接入（本轮落地）

- **`scripts/run_g5_ops_ledger.py`**：账本读写 + 两用例判定器（数据不足 → BLOCKED 如实，不虚构）
- **`run_g5_gate.py`**：case_g5_001/004 升级为「账本实测优先，无数据回退 BLOCKED」——与 002/003/005 同范式
- 账本路径：`docs/ops/g5-ops-ledger.json`（入库，可追溯）

## 五、执行排期建议

| 步骤 | 动作 | 前置 |
| ---- | ---- | ---- |
| 1 | 选定投放平台与 P0 内容分组（ep01–03） | 用户决策（平台账号） |
| 2 | P0 窗口 7 天采集（期间可正常产线作业） | 步骤 1 |
| 3 | 伯乐建议注入 P1 内容（ep04–06 发布策略）+ 台账起记 | 步骤 2 结束 |
| 4 | P1 窗口 7 天采集 + 台账 ≥4 周期 | 步骤 3 |
| 5 | `run_g5_gate.py` 复跑 → 001/004 判定 → G5 总裁决有望全 PASS | 步骤 4 |

> 窗口期约 2 周；期间产线/工程项（env.py、main.py 拆分等）可并行推进，互不阻塞。

## 六、风险与边界

- 平台数据获取若仅后台可见 → 人工周更录入账本（台账字段即录入表单）
- 样本不足 30 会话/集 → 顺延窗口或并集（如实留证，不放宽口径）
- P0/P1 内容代次混杂归因 → 已按「旧三章 vs 新三章」分组缓解；如需更强对照用同集双版本

## 七、平台矩阵与账号策略（2026-10-05 定案 v1.1.0）

### 7.1 选型依据（2026 行业情报 + 成片实态）

- 成片实态（ffprobe 核查）：六集均 **1920×1080 横屏 h264，单集 7.7–13.3s**——B站原生适配；抖音/TikTok/YT Shorts 属竖屏生态
- 行业实态（2026）：红果 AI 漫剧政策收紧（仿真人分成系数 60→40、AI 剧本保底大面积取消、万播 5–25 元）；B站充电专属被《心动禁区》S2 验证（7 天 5400+ 充电 ≈16 万）；TikTok Q1 短剧分账 2400 万美元、20 倍激励；DramaBox 开放 creator portal + 1.5 亿美元 AIGC 计划
- 合规：2026-04-01 起 AI 漫剧纳入分类分层审核，发布须勾选 **AIGC 标注**

### 7.2 平台矩阵（多选多推定案）

| 角色 | 平台 | 内容形态 | G5 判定 | 说明 |
| ---- | ---- | ---- | ---- | ---- |
| **G5 主平台** | **B站** | 横版原生 | ✅ 唯一入账 | 完播数据最细；充电付费验证；横屏零转制 |
| 国内流量 | 抖音 | 竖版分发 | ❌ 不入账 | 涨粉蓄水；竖版已产出 |
| 海外分发 | TikTok + YouTube Shorts | 竖版 | ❌ 不入账 | 待英配字幕后开号 |
| 长线卖剧 | DramaBox / YourChannel | 整季 pitch | — | 成片积累后 portal 投递（无需开号） |

> P0/P1 必须同平台同口径（§2.1）——判定采数只走 B站，其余平台纯分发。

### 7.3 账号策略：全部新建专号

| 决策因子 | 新建专号的优势 |
| ---- | ---- |
| G5 归因纯净 | P0/P1 同一新号，无历史内容污染完播率基线 |
| 垂类标签 | AI 漫剧标签从零精准培养，算法流量池不混乱 |
| 品牌统一 | YYC³ 体系命名（建议含品牌词+漫剧垂类词） |

例外：若已有**高粉丝量的影视/漫剧垂直号**可权衡复用（起量快 vs 归因混杂）；默认新建。

### 7.4 开号与 P0 首发清单

1. [ ] **B站新建专号**（手机号+实名）→ 上传横版 ep01-03 → 勾选 AIGC 标注 → 记录发布时间
2. [ ] **抖音新建专号**（实名）→ 竖版 `*_vertical.mp4` 同步分发（不入判定）
3. [ ] TikTok / YouTube：**待英配字幕后**再开号（Gmail 注册），避免空窗
4. [ ] DramaBox/YourChannel：攒满一季后投递（梗概+全剧大纲+2-3 样片）
5. [ ] B站创作者中心数据 → 每周录入账本 `completion`（P0 期 ep01-03）

### 7.5 竖版转制工程（已落地）

`scripts/run_vertical_transcode.py`：blur-pad 模式（背景模糊延展+原片等宽居中，零画面损失，优于中心裁切）；六集 1080×1920 竖版已产出至归档区 `output/*_vertical.mp4`（原横版保留）。
