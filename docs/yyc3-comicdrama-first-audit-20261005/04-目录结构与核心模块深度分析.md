## 三、Agent 代码三份拷贝漂移裁决（本轮最重要发现）

### 3.1 三份拷贝实态

| 维度 | docs 参考库（13py/2392行） | archive/components（16py/2680行） | 网关 core/agents（11py/1514行） |
| --- | --- | --- | --- |
| 定位 | 文档站规范副本（GitHub Pages 源） | 自称"可运行事实源" | **生产运行实体**（api/agent.py + agent_workers.py 生产 import） |
| 功能版本 | 冻结 09-26/27；drama_stage_adapter 落后 v1.3 | **最新**（G2 修订 09-27 + v1.3 双档位 10-02） | 09-25 Phase 0 基线 + 局部独立演进；**缺 G2-003/F1-F6/v1.3** |
| 同步机制 | 无（手工） | **不在 upstreams.tsv 清单（同步盲区）** | 上游 rsync 单向覆盖域 |

### 3.2 🔴 P0-6（新增）：生产安全规则漂移

`core/agents/zhiyun_shouhu_agent.py` 注入特征库 **8 条**，落后 components/docs 的 **12 条**——G2-003（2026-09-27）新增的「忽略之前所有指令」等 **4 条越狱变体未回合生产分支**（core 创建于 09-25，修订未回灌）。
**影响**：Step1 输入安全过滤可被已知变体绕过；**G2-003 验收跑的是 components 版——验收通过 ≠ 生产防护到位**，安全审计结论失真。

### 3.3 🔴 P0-7（新增）：双"单一事实源"声明冲突 + 无漂移发现机制

- `core/agents/__init__.py:10-11` 声明"单一事实源以本包为准" vs `docs/.../README.md:25` 声明"可运行代码事实源=components"——两处互相矛盾
- 三角无任何自动同步/比对机制，已实际双向漂移（core 缺 G2 修复；components 缺 core 工程化；docs 缺 v1.3）

### 3.4 🟠 P1-9（新增）：生产 orchestrator 缺 6 项已验收修复

core 版（243 行，生产运行）缺 components 版（276 行）的：F1 scene 参数、**F3 QC 复检 ≤2 轮循环（生产是单次放行！）**、F4/F6 trace_id 全链透传、F5 双 Agent 真并行、G2-002 场景裁剪、G2-006 序列化防御。
**影响**：生产九步闭环与总纲 §5 及 G2 验收语义不一致；质量不达标内容只优化一轮即出、无 trace 可审计。另：**drama_stage_adapter（含 v1.3 双档位，漫剧生产链核心）根本未进网关 core 域**——生产域漫剧链路空缺。

### 3.5 🟠 P1-10（新增）：core 版 base_agent 丢 max_tokens 防线

参考库有 `LLM_MAX_TOKENS=512`（思考模式长生成防线，M2 实测补充）；core 版 httpx 重写时静默丢失——生产调思考型模型可能长生成不受限（时延/成本放大）。

### 3.6 裁决建议（四步）

1. **止血（立即）**：G2-003 四条注入变体、F3 复检循环、G2-006 序列化防御、LLM_MAX_TOKENS 四项从 components 合入 core/agents（均为已验收缺陷修复，非新功能）
2. **定序（短期）**：统一两处声明为「可运行事实源 = core/agents（生产域）；components = 参考快照（只读）；docs = 规范展示（只读）」；upstreams.tsv 补记 components 豁免/排除说明
3. **回流（中期）**：core 工程化增强（progress_cb/sink/模型映射）patch 回流 components，或改为 core→components 单向导出脚本
4. **剥离（长期）**：docs 目录剥离 .py（保留 README/API.md，代码链接固定 commit），文档站不再承载可运行代码
