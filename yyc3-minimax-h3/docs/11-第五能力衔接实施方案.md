## 二、Phase 2.1 归档通道 ✅（本次交付）

**交付物**：[archive_to_nas.sh](../scripts/pipeline-tools/archive_to_nas.sh)

- **双速制**（修正 3）：manifest/report/analysis 走快车道（KB 级可实时）；媒体成品走慢车道（rsync `-z --partial`，Tailscale 2MB/s 断点续传）
- **降级自愈**：NAS 不可达 → 写 `.nas_pending` 队列，退出码恒 0 不阻断流水线；`--retry-pending` 在 NAS 恢复后补同步
- **配置**：`YYC3_NAS_SSH` / `YYC3_NAS_BASE` / `YYC3_NAS_PORT` 环境变量（默认 `yanyu@yyc3-nas:/Volume1/yyc3_hd`，对齐审核论证 §修正 2 的 NAS 目录规约 `video_batchXX/`）
- **验证**：本机 NAS 当前不可达 → 实测正确走降级入队闭环（`.nas_pending` 已有 batch01 欠账，NAS 恢复后 `--retry-pending` 自动补）

## 三、Phase 2.2 夜间批量 ✅（本次交付）

**交付物**：[nightly_run.sh](../scripts/pipeline-tools/nightly_run.sh)

- **窗口硬约束**（修正 1）：22:00–08:00 之外直接拒绝（Mac=主开发机，白天批量与开发争内存）；`H3_FORCE=1` 显式逃生阀供调试
- **全链路**：`pipeline_auto.py --auto` → NAS 双速归档 → 待队列补同步 → 面板数据刷新 → 次晨报告 `logs/nightly_YYYYMMDD.md`
- **安装**（cron，生产启用时执行）：

```bash
crontab -e
# 每晚 22:00 夜间批量（% 需转义）
0 22 * * * /Users/yanyu/YYC-Cube/YYC3-MiniMax-H3/scripts/pipeline-tools/nightly_run.sh >> /Users/yanyu/YYC-Cube/YYC3-MiniMax-H3/logs/cron_nightly.log 2>&1
```

- **已知本机注意**：PayGuard safe_rm 拦截器与 `set -u` 冲突（交互链路），两脚本已做防御（弃用 `set -u`、关键变量显式判空）；cron 直调 `/bin/bash` 不经过拦截器 wrapper，生产无影响

## 四、Phase 2.3 异步任务 API（规划，1-2 周）

按审核论证 §修正 2 设计稿执行，本文档固化接口契约供网关侧联调：

| 端点 | 方法 | 说明 |
| ---- | ---- | ---- |
| `/v1/video/tasks` | POST | 提交：`script/ref_image/params` → `{task_id, status:"queued"}` |
| `/v1/video/tasks/{id}` | GET | 轮询：`queued\|running\|scoring\|done\|failed` + progress + manifest_uri + video_uri(NAS) + scores |
| `/v1/video/tasks?limit=` | GET | 列表（治理中枢视角） |

- **网关侧**：NAS 网关新增 `video_tasks.py` 路由 + Redis 任务表
- **Mac 侧**：轻量 runner（拉队列 → `nightly_run.sh`/`pipeline_auto.py --auto` → 回写状态、产物 NAS 归档）
- **契约**：认证复用 X-API-Key/JWT；`X-YYC3-Task-Node: mac-yyc3-22` 披露生产节点；task 生命周期写 usage_log；灵韵 Agent 挂 `video_skill`（POST 任务 + 读结果两工具）
- **前置依赖**：Phase 2.1/2.2 稳定运行 ≥1 周
