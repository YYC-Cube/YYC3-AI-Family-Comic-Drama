## 四、多Agent协同架构适用性论证（核心结论）

### 4.1 结论：**可构建，且已在设计层三方收敛，推荐「分层接入」而非「推倒重构」**

| 证据 | 说明 |
| ---- | ---- |
| 协议同源 | 生产闭环 02/03 消息封套与 AI Family `a2a_protocol.py` 逐字段一致（msg_id/trace_id/msg_type/sender/receiver/task_type/payload/priority/timestamp/ttl） |
| 角色预置 | drama_stage_adapter 六阶段状态机 + `STAGE_OWNERS` 已将 H3 指派为阶段4 视听生成主责工具 |
| 执行件现成 | H3 侧 gateway claim（租约/心跳/互斥）与 manifest 单一事实源，即是「工具网关桩」等待替换的真实实现 |
| 治理件互补 | 智云守护（Step1 输入过滤/Step8 输出审计）恰好补齐 H3「口播文案内容合规」空白；格物宗师（≥80 分红线）可与 SyncNet+人工评分闭环融合 |

### 4.2 分层接入架构（推荐目标态）

```
L1 编排层（DGX 节点2）   AIFamilyOrchestrator · ReAct-C 九步 · 元启天枢 plan_tasks
                          ↓ 阶段4 AUDIOVISUAL_GEN：scene=F + Step7 质检重绘闭环
L2 传输层（适配器）       h3_production_adapter v2 —— A2A 语义 + 双传输绑定：
                          ├─ binding=gateway（默认）：转发至已落地 /v1/admin/video/tasks/claim
                          └─ binding=redis：Redis Stream（多节点横向扩展时启用）
L3 执行层（Mac 不动）     video_task_runner 四铁律 + pipeline_auto 五节点 + manifest 单一事实源
L4 治理层（横切）         智云守护安检 ↔ 12 告警聚合 ↔ 13 工单 ↔ RAG 知识沉淀
```

**关键决策**：A2A 是**语义协议**，gateway claim 是**传输绑定**——二者不是竞争关系。已落地链路的租约（180min）、心跳（480s）、互斥、白名单恰好修复了文档 02 的全部缺陷（600s TTL、无互斥、无重试）。**不要新起第二套调度通道**。

### 4.3 落地前提（阻断项）

1. 文档 02 的 `TASK_TIMEOUT=600` 必须 ≥ 4h（batch90/91 实测 6939~7158s/条），或改为「租约+心跳」语义
2. 全部子进程调用对齐铁律④（importlib/argv 数组注入，禁 `shell=True` 拼接）
3. batches/manifest 契约先归一（P1-C2），否则 Agent 回传的面板数据将出现双源真相

### 4.4 漫剧全链路收益预估

- 阶段1-3（创意→剧本→调度）：纯 DGX 侧 Agent 协同，零 H3 改造
- 阶段4（视听生成）：`DramaToolGateway.image_to_video` 桩 → 网关 claim 真实调用，H3 回传 manifest 全量指标（gen_seconds/score_norm/seed）直接供格物宗师质检
- 阶段5-6（合成→运营）：预见先知消费 nightly 报告做产能预测，知遇伯乐沉淀「形象×seed×评分」画像反哺排产 —— **H3 十批次生产数据即 RAG 冷启动语料**
