## 二、行业对标研究（External Benchmark）

### 2.1 模型生态（MiniMax-H3 / DiffSynth-Studio）

- DiffSynth-Studio 已将 MiniMax-H3 纳入官方模型家族，官方支持：**文生音视频、首尾帧引导生成、参考驱动生成、低显存推理、NF4 量化**，并提供 FL2VA/Ref2VA 的全量训练、LoRA 训练与验证代码
- H3-Base-Ref2VA 全模态参考能力：图像最多 9 张、视频最多 3 段（每段 2–15s，总时长 ≤15s）、首帧/尾帧/首尾帧三种引导模式
- 社区已出现 fl2va 首尾帧"无缝链式"多片段连续生成的实验性实践（cross-clip continuity）
- 结论：**首尾帧引导（fl2va 的 first_frame/last_frame）是当前项目完全未利用的原生能力**，可用于多镜头连续性与镜头切换稳定性，直接缓解"变脸/漂移"高频缺陷

### 2.2 推理优化最佳实践（Apple Silicon / MPS）

- 学术验证：CUDA→MPS 移植三要素——计时器替换（cuda.Event→perf_counter）、设备替换、**随机数生成器在 CPU 初始化后转移**（保证 MPS 可复现性）
- MPS 显存水位：`PYTORCH_MPS_HIGH_WATERMARK_RATIO=0.0` 可放开默认水印限制；但需配合内存压力监控（Activity Monitor 的 Memory Pressure 转橙/红即触发 swap，性能断崖）
- 小算子融合优先于并行化；LoRA 权重预合并（pre-merge）可显著降开销
- 结论：当前脚本未做**种子复现性对齐（CPU RNG）**、未记录**内存压力/耗时指标**、未提供**env 调优开关**——三项均为低成本高收益改进

### 2.3 评估体系最佳实践（客观指标）

- VBench / VBench-2.0：视频生成评测事实标准，含主体一致性、背景一致性、动态幅度等维度，人工评估采用**成对比较+Win Ratio**（比绝对打分更稳）
- 数字人口播专用：**SyncNet 置信度**（0~1，口型-音频同步度）是 LatentSync 等项目的核心自动化指标；THEval 补充面部质量、唇部动态、头部运动自然度维度
- 结论：人工 1~10 打分应升级为**「客观指标初筛 + 人工成对精评」双层漏斗**——SyncNet/一致性指标自动跑全量，人工只评 Top 候选，打分工作量降 60%+

### 2.4 LoRA 训练最佳实践

- 数据集结构化：prompt 列表 + 视频路径清单（CogVideoX 范式）；长视频先切场景（>5s 过滤）、再生成 caption、最后预缓存 latents/embeddings
- 数据量参考：角色 LoRA 最低 10–15 张图，推荐 20–50；动作细节需混入视频帧
- 结论：128G 内存可直接训练，但需先建**数据集准备脚本**（切分/caption/缓存），否则训练质量不可控

## 三、演进式扩展实施方案（Evolutionary Roadmap）

> 原则：不推翻现有闭环，逐层增强；每个 Phase 独立可交付、可回滚。

### Phase 1｜数据层统一（P0，改造收益最大）

**目标**：建立单一事实源，打通脚本↔面板。

| 任务 | 交付物 | 验收标准 |
| ---- | ------ | -------- |
| T1.1 统一批次 manifest | 每批次生成 `manifest.json`（prompt/参数/seed/文件路径/耗时/内存峰值） | pipeline_auto 全链路读写同一 manifest |
| T1.2 面板接真数据 | 面板读取 manifest.json + report.md 渲染 | 仪表盘数字与实际批次一致 |
| T1.3 共享 utils 抽象 | `scripts/lib/`（模型加载/vram_config/日志/manifest 读写） | 19个脚本重复代码收敛≥60% |

### Phase 2｜评估增强（P0，主观→客观）

| 任务 | 交付物 | 验收标准 |
| ---- | ------ | -------- |
| T2.1 SyncNet 口型置信度自动评分 | `pipeline-tools/score_lipsync.py`，全量 SUCCESS 样本自动打分写入 report 新列 | 全批次视频 100% 有客观分 |
| T2.2 首尾帧人脸一致性 | `pipeline-tools/score_consistency.py`（人脸embedding余弦相似度，首帧 vs 中段帧） | 变脸缺陷自动预警 |
| T2.3 成对比较精评模式 | analyze_report.py 增加 Win Ratio 汇总（Top5 候选两两对比） | 人工只评 Top 候选，工作量降 60% |
| T2.4 回归测试集 | 固定 3 参考图 × 3 固定 seed × 1 标准提示词，权重/环境变更后必跑 | 变更前后指标可对比 |

### Phase 3｜推理优化（P1，时间维）

| 任务 | 交付物 | 验收标准 |

### Phase 4｜能力扩展（P1，用足 H3 原生能力）

| 任务 | 交付物 | 验收标准 |

## 四、闭环反馈机制（Closed-Loop Feedback）

### 4.1 双闭环架构

```text
【微闭环 · 每批次】（已有，增强）
  生成 → 自动客观评分(SyncNet/一致性) → 人工Top精评(Win Ratio)
   ↑                                            ↓
 更新Seed/模板 ←── manifest.json 数据回流 ←── analyze_report

【宏闭环 · 每月/每版本】（新增）
  批次数据聚合 → export_multi_batch_summary → 演进路线复盘
   ↑                                            ↓
 Phase任务优先级调整 ←── 指标趋势(平均分/缺陷率/耗时) ←── 多批次对比
```

### 4.2 反馈触发规则（智能化约定）

| 信号 | 阈值 | 自动动作 |
| ---- | ---- | -------- |
| 缺陷占比 | 连续2批次同一标签 ≥30% | 面板预警 + 自动生成调参建议（查闭环框架表） |
| 客观分背离 | SyncNet 高但人工分低 | 提示检查音画内容相关性（口型对≠内容对） |
| 回归失败 | T2.4 回归集指标下降 >5% | 阻断权重/环境变更发布，回滚 .bak |
| 耗时劣化 | 帧生成速率下降 >15% | 触发内存压力检查规程（T3.3） |
| 无效迭代 | 连续3批次平均分提升 <0.2 | 停止seed探索，转Phase 4/5（换模板或训练LoRA） |

### 4.3 复盘节奏

| 频率 | 动作 | 产出 |
| ---- | ---- | ---- |
| 每批次 | 微闭环运行（现有 pipeline_auto 即可） | manifest + report + analysis_result |
| 每周 | export_multi_batch_summary 跨批复盘 | multi_batch_summary.md |
| 每阶段 | Phase 交付评审（对照本文档验收标准） | 本文档更新 + CHANGELOG |

### 4.4 度量北极星

- **主指标**：批次平均人工分（目标：3个迭代周期内 6.5 → 8.0）
- **过程指标**：客观/主观分相关系数（>0.6 说明自动初筛可信）、单视频耗时、缺陷率（变脸+手崩 <15%）
- **效率指标**：人工打分样本占比（目标 <40%）、无效迭代批次占比（<20%）

**技术要点（供后续迭代避坑）**：

1. **启发式评分演进路径**：固定分桶Pearson（0.54）→ 自适应分桶+滞后扫描（0.61）→ 帧级活跃度Pearson（0.71）→ **事件级最近邻匹配（0.98/0.76，最终采用）**
2. 三个实测坑：
   - AAC 编码使音轨时长漂移（2s 内容 → 2.05s），后段事件累计偏移 1 帧，固定滞后窗口无法吸收渐进漂移
   - 稀疏二值脉冲上的 Pearson 相关系数即使完全重合也只有 ~0.25（双零帧主导协方差），必须用事件级匹配
   - 滞后扫描窗口过宽（±15%）会让错位样本"找到"高相关滞后，事件级 ±1 帧容差即可
3. SyncNet 后端按 CPU 运行（权重小，离线批量不阻塞 MPS 生成）；`pip install syncnet-python` + 官方权重后自动启用
4. 机器实际 conda 环境为 `/opt/miniconda3/envs/modelscope`（文档规划的 h3-m4 未创建），需为该环境补装 `opencv-python`（已装，5.0.0）

关键性能结论：
- 第二个 seed 比第一个快 **18.6%**（torch.compile 预热摊销），后续大批次的边际耗时以 ~3h/条 为准
- **实测 ~468→278s/it**，NF4 反量化（CPU 侧）是瓶颈；Pruned vs NF4 A/B（P0-2）依然是下一个动作

**SyncNet 真实视频跑通（3 个新坑修复）**：

| 坑 | 根因 | 修复 |
| ---- | ---- | ---- |
| syncnet_python 0.2.2 导入静默变 None | `__init__.py` 把 ImportError 吞掉置 None；真实根因是 `scenedetect>=0.7` 移除了 `video_manager` 模块 | `pip install "scenedetect<0.7"` + 改从 `syncnet_python.syncnet_pipeline` 子模块导入以暴露真实错误 |
| 权重文件缺失且路径相对 | 包不带权重；`sfd_face.pth`/`syncnet_v2.model` 需从 Oxford VGG lipsync 页面下载，且 PipelineConfig 默认相对路径 | 下载到 `models/syncnet/`（86MB+52MB），代码显式传绝对路径 |
| **inference() 恒返 ok=False** | ① 默认 `min_face_size=100` 是 LRS2 大特写口径，本项目 480×832 半身像脸宽仅 ~55px；② AI 视频口型开合导致帧间人脸 IoU<0.5 频繁断轨（单轨最长 49 帧）；③ pipeline 内部 **scene 分段逐段 _track**，段内种子链断裂即弃轮 → 0 成轨 | 三参数调优 `min_face_size=40, min_track=25, num_failed_det=50` + **绕过 inference()**，自行复刻预处理后用**全局检测一次性喂 `_track`**（实测 seed42 成轨 2 条），再走 `_crop`→`evaluate` 取最大置信度 |

修复后实现收敛在 `h3_common.syncnet_score_impl`（含根因笔记注释），score_lipsync 调用方零改动。
