# 📖 全局释义与指导文档

> 定位：本项目（MiniMax-H3 数字人音视频本地生产线 · M4 Max 128GB）的**概念词典 + 标准作业流程（SOP）**。
> 读者：任何 AI 导师 / 开发者首次接触本项目，读完本文即可获得全局认知并安全上手。

---

## 一、项目一句话释义

**在 Apple M4 Max 128GB 本机，用 DiffSynth-Studio 驱动 MiniMax-H3 模型（NF4 量化，68GB 权重），批量生成"参考图 + 台词 → 口型同步数字人视频"，并以 manifest.json 为单一事实源，跑通「生成 → 自动口型评分 → 人工精评 → 数据分析 → 种子回写」的迭代闭环。**

---

## 二、核心概念词典（全局释义）

### 2.1 模型与推理

| 术语 | 释义 | 本项目取值/用法 |
| ---- | ---- | ---- |
| **MiniMax-H3** | MiniMax 开源的全模态音视频生成模型，一次前向同时产出视频帧与音频波形 | 基座模型，经 ModelScope 分发 |
| **Ref2VA** | Reference-to-Video+Audio 模式：参考图（人）+ 提示词（含台词）→ 说话数字人视频 | 本项目主力模式（口型同步） |
| **FL2VA** | First-Last-frame to Video+Audio 模式：文生音视频，支持首帧/尾帧/首尾帧引导 | 备用模式；首尾帧引导是 Phase 4 扩展点 |
| **NF4 量化** | bitsandbytes 4-bit 权重量化。推理时反量化回 bf16 计算，体积减半以上 | `MiniMax-H3-NF4` 仓，68GB 本地权重 |
| **Pruned 剪枝** | 非量化版本，层剪枝减体积。MPS 上原生 bf16，通常快于 NF4（反量化开销小） | `h3_pruned_*` 脚本；NF4 慢时的替代项 |
| **DiffSynth-Studio** | ModelScope 官方推理/训练框架，H3 的官方载体。pip 无包，需源码安装 | `vendor/DiffSynth-Studio`（可编辑安装） |
| **processor** | H3 的 tokenizer + 视频预处理器配置（`Ref2VA/processor/` 目录） | 本地化在 `/Users/yanyu/models/MiniMax-H3/` |

### 2.2 硬件与环境

| 术语 | 释义 | 本项目取值/用法 |
| ---- | ---- | ---- |
| **M4 Max 128GB** | Apple Silicon 统一内存芯片，CPU/GPU 共享内存池 | 无需显存 offload，全量加载可行 |
| **MPS** | Metal Performance Shaders，PyTorch 的 Apple GPU 后端 | `device="mps"`；等价于 CUDA 的角色 |
| **vram_limit** | DiffSynth 的显存水位控制参数 | 本项目设 96（GB），留系统余量 |
| **h3-m4 环境** | 本项目专用 conda 环境（Python 3.11 + torch 2.14 MPS） | `/opt/miniconda3/envs/h3-m4` |
| **统一内存水位红线** | 内存压力转橙/红即触发 swap，性能断崖 | 监控「内存压力」而非已用内存 |

### 2.3 数据与闭环

| 术语 | 释义 | 本项目取值/用法 |
| ---- | ---- | ---- |
| **manifest.json** | 批次单一事实源（schema_version=1）：参数/seed/状态/耗时/内存/客观分/人工分 | `output_batchXX/manifest.json`，原子写 |
| **批次隔离** | 每次批量运行独立目录 `output_batchXX/`，互不污染 | pipeline_auto 的 `--batch` 参数 |
| **口型分（score_norm）** | 客观音画同步分，0~1 归一化 | SyncNet 置信度映射 或 启发式评分 |
| **SyncNet 置信度** | 学术界口型同步标准指标（latent embedding 距离），约 10 为良好量级 | score_norm = conf/(abs(conf)+5) |
| **启发式评分** | 无 SyncNet 权重时的降级：音频 RMS 活跃度事件 vs 口型区运动事件做**事件级最近邻匹配**（±1 帧容差） | 合成验证：同步 0.978 / 错位 0.761 |
| **断点续跑** | 视频文件存在 + manifest 记录 SUCCESS 双确认才跳过 | 任意中断后重跑同一命令即可续 |
| **微闭环** | 单批次内的迭代：生成→评分→分析→更新seed | pipeline_auto v2 全自动串联 |
| **宏闭环** | 跨批次/跨月的复盘：多批汇总→指标趋势→演进路线调整 | export_multi_batch_summary + docs/04 第七章 |

### 2.4 已知坑位词典（实测沉淀）

| 坑 | 释义 | 正确姿势 |
| ---- | ---- | ---- |
| **AAC 时基漂移** | ffmpeg AAC 编码使音轨时长漂移（2s→2.05s），后段音画事件累计偏移 1 帧 | 评分用事件级 ±1 帧容差，勿用固定滞后 |
| **稀疏脉冲 Pearson 失效** | 二值活跃度脉冲即使完全重合，Pearson 也只有 ~0.25（双零帧主导） | 用事件集合匹配，勿用相关系数 |
| **vram_config 字符串坑** | `"cpu"/"mps"` 字符串在新版 torch 会 `to()` 报类型错 | 必须 `torch.device("cpu")` 对象 |
| **GitHub 403** | 本机网络无法直连 github clone | 用 `gitclone.com` 镜像 |
| **AI 终端回收杀后台** | AI 会话终端结束时连带 kill nohup 后台进程 | 长任务必须在用户系统终端启动 |
| **cv2/av ffmpeg 冲突** | opencv 与 pyav 各带一份 ffmpeg 动态库，objc 警告 | 目前无害；若崩溃先卸 opencv-contrib |
| **syncnet 静默降级** | syncnet 0.2.2 在 `scenedetect>=0.7` 下导入失败但 `__init__` 吞错置 None，表现是"无声降级到启发式" | `pip install "scenedetect<0.7"`；从子模块导入以暴露真实错 |
| **SyncNet 权重不随包分发** | 需手动下载 `sfd_face.pth`(86MB)+`syncnet_v2.model`(52MB) 到 `models/syncnet/`（Oxford VGG lipsync 页面） | 缺权重时 score_lipsync 自动降级启发式 |
| **inference() 恒返 ok=False** | 官方 pipeline 默认 `min_face_size=100`（LRS2大特写口径）+ scene 分段逐段 track，半身像视频 0 成轨 | 已绕过：`syncnet_score_impl` 全局检测一次喂 `_track`（min_face_size=40/min_track=25/num_failed_det=50） |

## 三、标准作业流程（SOP）

### 3.1 环境冷启动（新机器/重装后）

```bash
# 1. 环境（已有则跳过）
/opt/miniconda3/bin/conda create -n h3-m4 python=3.11 -y
git clone --depth 1 https://gitclone.com/github.com/modelscope/DiffSynth-Studio.git vendor/DiffSynth-Studio
/opt/miniconda3/envs/h3-m4/bin/pip install -e vendor/DiffSynth-Studio
/opt/miniconda3/envs/h3-m4/bin/pip install torch torchvision torchaudio bitsandbytes av imageio syncnet-python

# 2. 权重（本地已有则跳过下载）
#    /Users/yanyu/models/MiniMax-H3-NF4/     ← 四件套 + FL2VA/Pruned 备份
#    /Users/yanyu/models/MiniMax-H3/Ref2VA/processor/  ← tokenizer
#    代码通过 h3_common.LOCAL_WEIGHTS_ROOT 自动发现，无需配置

# 3. 参考图
mkdir -p ref_images   # 放入人物参考图（jpg/png/webp）
```

### 3.2 批量生产（每日主流程）

```bash
cd /Users/yanyu/YYC-Cube/YYC3-MiniMax-H3

# ① 编辑 scripts/batch_ref2va_nf4.py 配置区（PROMPT/SEED_LIST），或直接用 pipeline_auto
# ② 系统终端启动（⚠️ 勿在 AI 会话终端跑长任务）
nohup /opt/miniconda3/envs/h3-m4/bin/python scripts/batch_ref2va_nf4.py --batch 01 > logs_batch01_run.log 2>&1 &
tail -f logs_batch01_run.log

# ③ 生成完成后：自动口型评分（SyncNet 优先，无权重自动降级启发式）
/opt/miniconda3/envs/h3-m4/bin/python scripts/score_lipsync.py --batch 01

# ④ 人工精评：打开 report_batch01.md，填「评分(1~10)」「缺陷标签」列

# ⑤ 分析（耗时基线/口型分统计/主客观背离）→ 更新最优 seed 回脚本
/opt/miniconda3/envs/h3-m4/bin/python scripts/pipeline-tools/analyze_report.py --batch 01
/opt/miniconda3/envs/h3-m4/bin/python scripts/pipeline-tools/update_seed_list.py --batch 01
```

### 3.3 一键流水线（推荐日常用）

```bash
/opt/miniconda3/envs/h3-m4/bin/python scripts/pipeline-tools/pipeline_auto.py
# 串联：生成 → 自动评分 → （暂停，等人工填分）→ 分析 → 更新seed
```

### 3.4 故障处置速查

| 症状 | 处置 |
| ---- | ---- |
| 中断后重跑 | 直接重跑同命令，manifest 断点续跑 |
| `to() invalid combination` 报错 | 确认 h3_common 用 torch.device 对象（已修复） |
| 内存压力转橙/红 | 停批，减小 num_frames 或换 Pruned 版，关大内存应用 |
| 评分全 None | `ffmpeg` 不在 PATH，或视频无音轨（FAILED 记录不评分属正常） |
| SyncNet 未生效 | `pip install syncnet-python` 后首次运行会拉官方权重（需网络） |
