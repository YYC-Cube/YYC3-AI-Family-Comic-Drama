# 🧭 MiniMax-H3 智能化落地生产可用方案论证

> **目标**：将现有「CLI 闭环流水线」升级为「可视化操作页面 / 插件化生产线」，实现全链路闭环投产。
> **论证方法**：调取同类型（AI 视频生成管线）高可用及拓展核心技术流，逐一对照本项目真实代码结构，给出可落地路径。

---

## 一、同类核心技术流对标（Industry Benchmark）

| 技术流 | 核心机制 | 可借鉴点 | 与本项目匹配度 |
| ------ | -------- | -------- | :---: |
| **ComfyUI**（行业标准） | 节点式 DAG 执行器 + workflow JSON 可移植 + 懒加载（只重算变更下游） | ① 流程 JSON 化=可版本化 ② 节点有状态（模型不重复加载）③ 产物自描述（元数据内嵌） | ★★★★★ |
| **comfyui-ai-studio**（Next.js 壳模式） | 本地引擎 + Next.js Studio 前端；SSE 事件总线 + 拓扑排序 DAG 调度 + 本地文件存储（local-first，零云端依赖）+ 运行历史持久化 + WebSocket 心跳重连 | ① 引擎与壳分离 ② manifest 即数据源 ③ SSE 推送进度 ④ SSRF/鉴权安全清单 | ★★★★★ |
| **Gradio / Streamlit** | 装饰器即 UI，分钟级 MVP | 快速验证面板可行性（原型期） | ★★★☆☆ |
| **DiffSynth-Studio 原生** | Pipeline 对象化 + vram management 分层 | 本项目已 vendor 内嵌，天然插件宿主 | ★★★★☆ |

**关键论断**：本项目 `manifest.json` 单一事实源设计与 ComfyUI「workflow JSON + 产物元数据自描述」同构；`h3_common.py` 共享库相当于引擎层，**缺的只是一层「数据桥 + 壳」**——这正是从模拟数据面板走向生产可用面板的唯一缺口。

## 三、三路线方案论证

### 路线 A：数据桥接增强（渐进式 · 推荐「本周可落地」）

**架构**：`manifest.json → export_json.py（file-watcher/CLI 导出）→ 面板 fetch 静态 JSON`

```
┌────────────┐   pipeline 跑完自动触发   ┌──────────────┐
│ pipeline_  │ ───────────────────────▶ │ export_      │
│ auto.py    │   （新增钩子，5行代码）    │ dashboard_   │
└────────────┘                          │ data.py      │
                                        └──────┬───────┘
                                               │ 写出
                                               ▼
                                    dashboard/data/batches.json
                                               │
                              ┌────────────────┴────────────────┐
                              │  Ref2VA-面板.html（已有壳）      │
                              │  fetch('./data/batches.json')   │
                              │  ECharts 真实渲染               │
                              └─────────────────────────────────┘
```

| 维度 | 评估 |
| ---- | ---- |
| 成本 | **1 个脚本 + 面板 3 处改动**，半天 |
| 优点 | 零新依赖、零服务进程、离线可用、与断点续跑天然兼容 |
| 缺点 | 只读（不能从面板触发生成）、需手动/钩子刷新 |
| 适用 | 单机研究者日常迭代（当前 M4 Max 场景完全够用） |

**落地清单**：
1. `scripts/pipeline-tools/export_dashboard_data.py`：聚合 `output_batch*/manifest.json` + `report_batch*.md` → `dashboard/data/batches.json`（含成功率/评分趋势/缺陷分布/跨批对比四组数据，字段与面板 ECharts 一一对应）
2. 面板 HTML：`MOCK_DATA` 常量替换为 `fetch()`，加载失败降级到模拟数据（保底可用）
3. `pipeline_auto.py` 末尾追加钩子：步骤⑤完成后自动调用导出脚本（闭环自动化，符合「五标·自动化」）

### 路线 B：Next.js 可视化控制台（生产级 · 推荐「DGX Spark 迁移期启动」）

**架构**：对齐 comfyui-ai-studio 验证过的模式——**本地引擎 + Next.js App Router 壳 + SSE 实时回传**

```
Next.js 14+ App Router（RLT 团队技术栈原生匹配）
├── app/(dashboard)/page.tsx          仪表盘（RSC 读 manifest 目录）
├── app/pipeline/page.tsx             流水线控制（client + SSE）
├── app/batches/[id]/page.tsx         批次详情（视频缩略图网格）
├── app/api/pipeline/run/route.ts     POST 触发 pipeline_auto.py（spawn 子进程）
├── app/api/pipeline/stream/route.ts  SSE：tail 日志 + manifest 变更事件
├── app/api/score/route.ts            人工精评表单提交（写回 report_batchXX.md）
└── lib/manifest.ts                   manifest.json zod schema + 读取器
```

| 维度 | 评估 |
| ---- | ---- |
| 成本 | 2~3 周（复用现有面板的模块划分与交互设计稿） |
| 优点 | ① 与 YYC³ 团队 Next.js+shadcn/ui+Radix 标准栈一致 ② SSE 实时进度（对齐 comfyui-ai-studio 的 event bus 设计）③ shadcn/ui 组件天然覆盖「表格/抽屉/表单」需求 ④ DGX Spark 上以 `next start` 常驻，多人局域网可访问 |
| 缺点 | 需 Node 运行时；子进程管理需处理僵尸进程与并发锁 |
| 安全要点 | 仅绑定 `127.0.0.1` 或局域网 + Bearer Token；spawn 白名单（只允许 pipeline_auto.py）；SSRF 防护（对齐 benchmark 清单） |

**关键技术决策**（论证）：
- **为什么不用 Gradio？** Gradio 快但交互受限于其表单范式，无法承载「批次抽屉 + 跨批对比 + 评分趋势」这类已有明确设计稿的管理后台形态；且与团队五标「标准化」相悖。
- **为什么 RSC 优先？** manifest 是文件系统静态数据，Server Components 直接 `fs.readFile` 渲染，零 API 层即可完成仪表盘 80% 功能；仅「运行控制」和「实时日志」走 Client + SSE——服务端/客户端边界与数据特性完全吻合。

### 路线 C：插件化 / 生态化（长期 · 生态位最高）

**C1. DiffSynth-Studio 插件形态**（本项目 vendor 已内嵌宿主）
- 将 `h3_common.py` 的 load_pipeline + vram_config 封装为 `diffsynth.pipelines` 的一等公民
- 上游 PR 潜力：MiniMax-H3 的 M4 Max MPS offload 配置目前是社区空白（`minimax_h3_audio_video.py` 官方仅 CUDA 路径），贡献回去即建立技术影响力（五化·生态化）

**C2. ComfyUI Custom Node 形态**（触达最大分发网络）
- 包装「加载权重 → Ref2VA 采样 → 口型评分」为 3 个节点，workflow JSON 可分享复现（对齐 ComfyUI「产物自描述」核心机制）
- 2026 年 ComfyUI 已是 AI 生成事实标准，节点包 = 免费分发渠道

**C3. pnpm workspace Monorepo 化**（工程承载）
```
yyc3-minimax-h3/
├── apps/console/          ← 路线 B Next.js 控制台
├── packages/manifest-schema/  ← zod schema 共享包（Python 导出与 TS 读取共用契约）
├── packages/ui/           ← 批次卡片/评分条等跨项目复用组件
└── engine/                ← 现有 scripts/（Python 引擎，不迁移）
```
> schema 契约先行：`manifest.schema.json`（JSON Schema 双端生成）保证 Python 写与 TS 读永不错位——这是三形态并存的**唯一强约束**。

## 四、路线对比与决策矩阵（五维评估）

| 评估维 | 路线 A 数据桥 | 路线 B 控制台 | 路线 C 插件生态 |
| ------ | :---: | :---: | :---: |
| 时间维（落地速度） | ★★★★★ 半天 | ★★☆ 2-3周 | ★★ 持续演进 |
| 空间维（结构侵入） | ★★★★★ 零侵入 | ★★★ 新增 app | ★★ 重构边界 |
| 属性维（生产强度） | ★★★ 只读 | ★★★★★ 可操控+可审计 | ★★★★ 分发广 |
| 事件维（交互闭环） | ★★ 手动刷新 | ★★★★★ SSE 实时 | ★★★ 依赖宿主 |
| 关联维（生态价值） | ★★ 自用 | ★★★★ 团队复用 | ★★★★★ 社区影响力 |

### 决策：**A → B → C 三步走（非互斥，层层叠加）**

```
Phase 1（即刻）    路线A：export_dashboard_data.py + 面板fetch化
                  ▸ 产出：真实数据可视化，零风险
Phase 2（迁移期）  路线B：Next.js 控制台（apps/console）
                  ▸ 产出：生产操作页面，SSE 实时闭环，与 DGX Spark 部署同步上线
Phase 3（生态期）  路线C：manifest schema 契约 → DiffSynth 上游 PR → ComfyUI 节点包
                  ▸ 产出：技术影响力 + 分发渠道
```

## 六、风险与对策

| 风险 | 对策 |
| ---- | ---- |
| 面板 fetch 本地 file:// 被 CORS 拦截 | 导出脚本同时生成 `data/` 内 JSON；用 `python -m http.server` 或面板改用 `<script src>` JSONP 式加载（零服务方案） |
| Next.js 子进程长任务超时 | SSE 心跳 + 断线重连（对齐 benchmark 的 ping/pong 设计）；manifest 断点续跑兜底 |
| 双端 schema 漂移 | JSON Schema 契约 + CI 校验（git 建仓后接入） |
| 大文件入库（模型/视频） | .gitignore 已备；schema 包单独发版 |
