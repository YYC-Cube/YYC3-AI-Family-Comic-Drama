## 2. 文档版本控制与更新流程

### 2.1 版本规则（语义化）

- **主版本 vX.0.0**：文档定位/结构重构、读者对象变化。
- **次版本 vX.Y.0**：新增章节、完成一轮系统性更新（如 06 v1.1→v1.2 增补工作指导）。
- **修订版 vX.Y.Z**：错别字/链接/小幅澄清。
- 每次变更必须同步更新 front matter 的 `version` 与 `updated` 字段。

### 2.2 更新流程（谁改、何时改、怎么改）

```
触发 → 定位文档 → 按 2.1 升版本 → 内容更新 → 交叉引用检查 → 落变更记录
 │
 ├─ 会话收尾：必更 06（状态快照）+ 04（里程碑归档）
 ├─ 接口变更：必更 08（API + 契约）→ 若字段变化同步 06 风险区
 ├─ 新坑/新概念：必更 02 / 05 词典
 ├─ 环境变更：必更 01，并回归 py_compile 冒烟
 └─ 重大情报（新模型/新方法）：更新本文 §3，并在 06 建议区挂动作项
```

### 2.3 交叉引用与一致性纪律

1. 引用一律用相对链接（`[06](06-项目现状分析与后续建议.md)`），不写绝对路径。
2. 引用具体结论时标注小节号（如「见 08 §4 数据契约」），小节号变更需全文搜索修正。
3. 事实冲突时优先级：**代码与 manifest 实际状态 > 06 > 04 > 其余**。
4. 每次新增文档：更新 README 索引 + 本文 §1 矩阵（两处缺一不可）。

### 3.2 同类数字人方案横向对比（技术选型参考）

| 方案 | 技术路线 | 实时性 | 口型精度 | 与本项目关系 |
| ---- | ---- | ---- | ---- | ---- |
| **MiniMax-H3（本项目）** | 全模态 DiT，视频+音频联合扩散生成 | 离线（分钟~小时级） | 原生音画联合建模，语义级同步 | 基座本身；音频是生成而非驱动信号 |
| MuseTalk 1.5（腾讯） | VAE latent 单步 inpainting 改口型 | **30fps+ 实时**（V100） | 中（256×256 唇区，需 GFPGAN 补后处理） | 互补：若未来做「已有视频重配音」，可叠加 MuseTalk 做后端 |
| Wav2Lip | 语音驱动唇形 GAN | 快 | 低（分辨率受限，下颌伪影） | 历史基线，不采用 |
| SadTalker | 单照片 3DMM 驱动全头 | 离线 | 中 | H3 Ref2VA 已覆盖同类输入（单图→说话视频），且音画原生同步更强 |
| Hallo / EchoMimic | 音频驱动肖像动画（扩散） | 离线 | 中高 | 同赛道竞品；H3 差异化在原生立体声音频 |
| LatentSync | 视频唇部扩散重同步 | 离线 | 高（多步扩散） | 口型修复备选；其评估方法直接用 SyncNet（见 3.3） |

**选型判断**：本项目「单参考图 → 音画同步口播」的正解仍是 H3 Ref2VA；Turbo LoRA 解决速度后，暂无更换基座的理由。MuseTalk/LatentSync 仅作为「成品视频改配音」的潜在后处理储备。

### 3.3 SyncNet 评估基准校准（重要发现）

行业以 SyncNet 的 **LSE-C（置信度）/ LSE-D（距离）** 为口型同步标准指标：

| 参照 | SyncNet conf | 说明 |
| ---- | ---- | ---- |
| D-ID（宣称行业第一的实时 avatar 平台） | **8.67** | 其官网以 SyncNet conf 作为营销指标 |
| 学术界「良好同步」经验阈值 | > 6 左右 | 多篇 talking-head 论文的隐含口径 |
| **本项目 batch01 实测** | 1.66 ~ 1.90 | ⚠️ 显著低于行业良好线 |

**校准分析**（三因素假设，待 A1 人工精评裁定）：
1. **内容差异**：行业基准多为面部大特写；本项目 480×832 半身像，脸宽仅 ~55px，SyncNet 在小脸上的判别力天然下降。
2. **任务差异**：行业产品是「给定音频驱动唇形」（同步是硬约束）；H3 是「音画联合生成」（同步是软涌现），存在系统性相位漂移空间——与 av_offset -11/-15 观察一致。
3. **绝对值不可跨设定比较**：本项目 score_norm 仅批次内相对比较有效（已在 08 §7 固化为纪律）。

**可操作结论**：
- 若 A1 人工确认口型主观可接受 → 差异主要来自因素 1，维持现口径并在 report 标注「半身像口径」。
- 若人工确认明显错位 → 升级为 P0：调研推理侧音画相位对齐（av_offset 补偿）或评估 Turbo LoRA 是否改善（少步采样可能减少漂移累积）。

## 4. 智能化闭环文档

> 目标：让「数据→洞察→动作→验证」在文档体系中自动衔接，而不是散落在会话记忆里。

### 4.1 闭环架构

```
        ┌────────────────────────────────────────────────┐
        │                智能化闭环总览                     │
        │                                                │
        │  ① 数据层   manifest.json（单一事实源）           │
        │      ↓ flat_rows()                            │
        │  ② 分析层   analyze_report.py → analysis_*.md  │
        │      ↓ 客观/主观对照 + 耗时基线                  │
        │  ③ 决策层   06 文档 §四 任务表（A1~A6）          │
        │      ↓ 时间节点/责任人/资源/验收标准              │
        │  ④ 执行层   脚本改造 / 批次运行 / 人工精评        │
        │      ↓ 产物回写 manifest + report              │
        │  ⑤ 归档层   04 文档里程碑 + 02/05 坑位词典        │
        │      ↓                                         │
        │  ⑥ 校准层   本文 §3 情报 + §2 版本流程           │
        │      └──────→ 回到 ①（下一批次）                 │
        └────────────────────────────────────────────────┘
```

### 4.2 技术落地路径（当前闭环的三个增强点）

| 增强点 | 现状 | 落地路径 | 预期效果 | 验证方式 |
| ---- | ---- | ---- | ---- | ---- |
| 客观指标扩容 | 仅口型分 | A5 人脸一致性分（embedding 余弦）入 manifest | 双客观指标交叉预警「变脸」 | 对人工标「变脸」样本回测命中率 |
| 速度迭代 | 3.2h/条（NF4/50 步） | A2 Pruned A/B → A6 Turbo LoRA 评估，阶梯降本 | 目标 <1.5h/条（Pruned）→ <1h/条（Turbo，若质量达标） | manifest gen_seconds 同 seed 对比 |
| 人工成本 | 每条全量精评 | T2.3 成对精评：仅评 Top5 候选 | 人工打分量 -60% | 两轮人工结论一致性抽检 |

### 4.3 持续优化机制（滚动触发器）

1. **批次触发**：每个新批次 analyze 后，若「客观高/人工低」或「客观低/人工高」样本占比 >30% → 重校评分口径（回 3.3 三因素分析）。
2. **情报触发**：每月一次检索 DiffSynth-Studio / LightX2V release notes（H3 生态活跃，2026-08 一个月内 3 个 Turbo 版本）。
3. **劣化触发**：回归测试集（A4）任一指标较历史均值跌 >15% → 冻结量产，先二分环境/权重变更。
4. **文档触发**：schema_version 升级、Turbo 采纳、av_offset 结论三事件任一发生 → 08 契约与 06 任务表强制同步。

### 4.4 预期效果评估基线（供季度复盘）

| 指标 | 2026-09-03 基线 | 2026-12 目标 |
| ---- | ---- | ---- |
| 单条生成成本 | 3.2h | <1.5h（Pruned/Turbo 二选一落地） |
| 人工精评投入 | 全量 | Top5 成对精评（-60%） |
| 客观指标数 | 1（口型分） | 2（+人脸一致性） |
| IDE/工具链诊断 | 0 Error 0 Hint | 维持 0 |
| 文档体系 | 01~09 全量 | 按本文 §2 流程滚动维护 |
