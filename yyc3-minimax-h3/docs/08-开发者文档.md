```bash
/opt/miniconda3/envs/h3-m4/bin/python scripts/pipeline-tools/pipeline_auto.py
```

```bash
PY=/opt/miniconda3/envs/h3-m4/bin/python
# ① 生成（~3.2h/条，见 06 文档基线）

# ③ 人工：打开 report_batch01.md 填「评分(1~10)」「缺陷标签」

$PY scripts/pipeline-tools/analyze_report.py --batch 01
# ⑤ 最优 seed 回写主脚本
$PY scripts/pipeline-tools/update_seed_list.py --batch 01
```

## 3. API 参考

### 3.1 h3_common（共享库）

模块路径：`scripts/lib/h3_common.py`

#### `load_pipeline(variant="nf4", pipeline="ref2va", vram_limit=96) → MiniMaxH3Pipeline`

统一模型加载入口（收敛 19 个旧脚本的重复加载逻辑）。

| 参数 | 类型 | 说明 |
| ---- | ---- | ---- |
| `variant` | `str` | `"nf4"`（4bit 量化）或 `"pruned"`（bf16 剪枝版） |
| `pipeline` | `str` | `"fl2va"`（文/图生音视频）或 `"ref2va"`（参考图生音视频） |
| `vram_limit` | `int` | DiffSynth 显存限制（GB），M4 Max 128GB 下默认 96 |

行为要点：

- 本地权重自动发现：`/Users/yanyu/models/MiniMax-H3-NF4/`（可用 `H3_WEIGHTS_DIR` 环境变量覆盖）存在四件套时直接用本地文件，跳过在线下载。
- processor 同理：`MiniMax-H3/{PIPELINE}/processor/` 本地存在即离线加载。
- 返回的 pipeline 已配置 MPS + bf16 计算（`m4_max_vram_config`）。

#### `class Manifest`

批次单一事实源（schema_version=1，原子写 `save()`）。

| 方法 | 签名 | 说明 |
| ---- | ---- | ---- |
| `Manifest(path, batch, variant, pipeline, params)` | 构造 | 新建 manifest |
| `Manifest.load(path)` | classmethod | 读取已有 manifest |
| `.save()` | | **原子写**（tmp + replace，断电不损坏） |
| `.add_record(ref_img, seed, status, video_path, **perf)` | | 追加记录；status ∈ `SUCCESS/FAILED/SKIPPED/READ_FAILED` |
| `.find(ref_img, seed)` | | 按 (参考图， seed) 查记录，无则 `None` |
| `.set_lipsync(ref_img, seed, backend, confidence, av_offset, score_norm)` | | 回填自动评分 |
| `.set_human(ref_img, seed, score=None, tags=None)` | | 回填人工评分 |
| `.finish()` | | 写 `ended_at` 并保存 |
| `.flat_rows()` | generator | 展平记录（lipsync/human 拆列），供 analyze 消费 |

#### `class PerformanceTimer`

上下文管理器：耗时 + RSS 峰值 + MPS 已分配显存。

```python
with PerformanceTimer() as t:
    do_inference()
print(t.seconds, t.peak_rss_gb, t.mps_alloc_gb)
```

#### `syncnet_score(video_path: Path, work_dir: Path) -> Optional[dict]`

SyncNet 官方后端评分。内部实现 `syncnet_score_impl` 的关键差异：**不调用 `pl.inference()`**（其 scene 分段逐段 `_track` 在本项目半身像视频上 0 成轨），而是复刻预处理后全局检测一次性喂 `_track` → `_crop` → `evaluate`，取最大置信度轨。

返回值（失败返回 `None`，调用方降级）：

```python
{
  "backend": "syncnet",
  "confidence": 1.8957,          # 原始 SyncNet 置信度
  "av_offset": -11,              # 音画偏移（帧，负=音频滞后视频）
  "score_norm": 0.2749,          # conf/(abs(conf)+5)，仅批次内可比
}
```

#### `heuristic_sync_score(video_path: Path, work_dir: Path) -> dict`

降级后端（无需权重）。音频活动事件 vs 口型区运动事件的**事件级最近邻匹配**（容差 1 帧），对 AAC 时长漂移鲁棒。返回结构同上（`backend="heuristic"`）。历史背景：早期 Pearson/Jaccard 方案在稀疏脉冲上失效，事件匹配是第二版实现。

#### 常量

| 常量 | 值 | 说明 |
| ---- | ---- | ---- |
| `MODEL_ID_NF4` | `DiffSynth-Studio/MiniMax-H3-NF4` | 在线下载回退 |
| `MODEL_ID_PRUNED` | `DiffSynth-Studio/MiniMax-H3-Pruned` | 同上 |
| `PROCESSOR_ID` | `MiniMax/MiniMax-H3` | processor 在线回退 |
| `LOCAL_WEIGHTS_ROOT` | `$H3_WEIGHTS_DIR` 或 `/Users/yanyu/models` | 本地权重根 |

## 4. 数据契约：manifest.json

**schema_version = 1**（完整示例见 `h3_common.py` 模块 docstring）。

关键字段语义：

| 字段 | 类型 | 语义 | 写入方 |
| ---- | ---- | ---- | ---- |
| `records[].status` | enum | `SUCCESS`/`FAILED`/`SKIPPED`/`READ_FAILED` | 生成脚本 |
| `records[].gen_seconds` | float\|null | 该条生成耗时（秒） | PerformanceTimer |
| `records[].peak_rss_gb` | float\|null | 进程 RSS 峰值 | PerformanceTimer |
| `records[].mps_alloc_gb` | float\|null | MPS 已分配显存（采样时点） | PerformanceTimer |
| `records[].lipsync` | object\|null | 自动评分（backend/confidence/av_offset/score_norm/scored_at） | score_lipsync |
| `records[].human` | object | `{score: 1~10\|null, tags: "变脸,口型错位"...}` | 人工填写 + analyze 读取 |

**契约纪律**：

- manifest 是唯一事实源；report md 只是人工视图，两者由 `score_lipsync.refresh_report` 保持同步。
- 断点续跑判定 = 视频文件存在 **且** manifest 记录 `SUCCESS`，二者缺一不可。
- 合法缺陷标签集合（analyze 硬编码）：`变脸 | 手崩 | 抖动 | 口型错位`。

## 5. 代码示例（Cookbook）

### 5.1 程序化生成单条视频（复用共享库）

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).parent / "scripts" / "lib"))

from h3_common import load_pipeline, PerformanceTimer

pipe = load_pipeline(variant="nf4", pipeline="ref2va")
with PerformanceTimer() as t:
    video, audio = pipe(
        prompt="固定机位半身人像，口型与台词精准同步……",
        height=480, width=832, num_frames=124,
        num_inference_steps=50, seed=42,
        references=[{"type": "image", "image": ref_image}],
    )
# 落盘
from diffsynth.utils.data.audio_video import write_video_audio
write_video_audio(video=video, audio=audio, output_path="out.mp4",
                  fps=24, audio_sample_rate=32000)
```

### 5.2 对已有视频打口型分（自动降级）

```python
from h3_common import syncnet_score, heuristic_sync_score

result = syncnet_score(Path("out.mp4"), Path("_work"))
if result is None:                      # 权重缺失/成轨失败等
    result = heuristic_sync_score(Path("out.mp4"), Path("_work"))
print(result["backend"], result["score_norm"])
```

### 5.3 新增一种 variant（如未来 Turbo 蒸馏版）

1. `h3_common.py` 增加 `MODEL_ID_TURBO = "lightx2v/Minimax-h3-Turbo"` 与 `weight_files` 后缀逻辑。
2. `batch_ref2va_nf4.py` 的 `VARIANT` 注释扩为 `nf4 | pruned | turbo`。
3. 先跑 A/B（同 seed 同 prompt），用 manifest `gen_seconds` 对比后再切量产。

## 6. 端到端流程图与状态机

### 6.1 端到端数据流（Flow）

```
ref_images/*.png ──┐
SEED_LIST ─────────┤
PROMPT ────────────┤
                   ▼
        ┌─────────────────────┐   加载一次   ┌────────────────┐
        │ batch_ref2va_nf4.py │◄───────────►│ load_pipeline  │
        └─────────┬───────────┘             └───────┬────────┘
                  │ 逐(图,seed)生成                   ▼
                  │                       vendor/DiffSynth-Studio (MPS)
                  ▼
     [断点续跑检查：文件存在 ∧ manifest=SUCCESS ?]──是──► 跳过
                  │否
                  ▼
          生成 video+audio → write_video_audio → h3_seed_{seed}.mp4
                  │
                  ▼
        manifest.add_record(status, gen_seconds, peak_rss_gb) ──► manifest.json（原子写）
                  │
                  ▼
        score_lipsync.py：syncnet_score() ─失败/无权重─► heuristic_sync_score()
                  │
                  ▼
        manifest.set_lipsync(...) + report 口型分列刷新
                  │
                  ▼ （人工暂停点：填 评分1~10 + 缺陷标签）
        analyze_report.py ──► analysis_result_batchXX.md（客观/主观对照 + 耗时基线）
                  │
                  ▼
        update_seed_list.py ──► SEED_LIST 回写主脚本（下一批次迭代）
```

### 6.2 单条记录状态机（State Machine）

```
            ┌──────────────┐   视频文件+manifest双确认     ┌──────────────┐
   新任务 ──►│   PENDING    │──────────────┬─────────────►│   SKIPPED    │
            │ (无记录)      │              │              └──────────────┘
            └──────┬───────┘              │
                   │ 开始推理              │ 参考图读取失败
                   ▼                      ▼
            ┌──────────────┐        ┌──────────────┐
            │  GENERATING  │        │ READ_FAILED  │
            └──────┬───────┘        └──────────────┘
                   │ write_video_audio 成功？
          成功 ┌───┴───┐ 失败
               ▼       ▼
        ┌─────────┐ ┌────────┐
        │ SUCCESS │ │ FAILED │──重跑（覆盖记录）──► GENERATING
        └────┬────┘ └────────┘
             │ score_lipsync
             ▼
        ┌──────────────────┐   syncnet 失败/无权重
        │ LIPSYNC:syncnet  │──────────────► LIPSYNC:heuristic
        └────┬─────────────┘
             │ 人工精评
             ▼
        ┌──────────────────┐
        │ HUMAN: score/tags│ ──► analyze 汇总 → 选种 → 下批次
        └──────────────────┘
```

### 6.3 syncnet_score 内部决策流（时序要点）

```
导入 syncnet_python.syncnet_pipeline（⚠️ 必须子模块路径，__init__ 会吞 ImportError）
  │ 权重存在？ models/syncnet/{sfd_face.pth, syncnet_v2.model}
  ▼
ffmpeg: 恒定25fps AVI → 抽帧 %06d.jpg → 16k mono wav
  ▼
S3FD 逐帧人脸检测（conf_th=0.9, min_face_size=40）
  ▼
pl._track(detections)   ←── 关键：全局一次成轨（绕过官方 inference() 的 scene 分段）
  │ 有轨？ 否 → return None（调用方降级 heuristic）
  ▼
逐轨 _crop → 解帧+抽音 → pl.syncnet.evaluate → (av_offset, conf)
  ▼
取 conf 最大轨 → score_norm = conf/(abs(conf)+5)
```

## 7. 最佳实践

### 7.1 参数与配置

1. **种子策略**：探索期每图 2~3 seed；`SEED_LIST` 必须单行书写（`update_seed_list.py` 正则依赖）。
2. **prompt 结构**：沿用五段式（主体定义/视频概要/保留分析/画面描述/音频描述 + 禁止项），`<Subject1>` 占位符对应参考图人物。
3. **批次规模**：首轮验证 ≤ 4 任务（2 图 × 2 seed），确认质量后再放量；以 3.2h/条做排产。
4. **权重变更加固**：每次换权重/环境后先跑回归测试集（规划中，见 06 文档 P1）。

### 7.2 工程纪律（本项目踩坑换来的）

1. **一切以 manifest 为准**：不要手改 `output_batchXX/manifest.json`；人工输入只进 report 的「评分/缺陷标签」两列。
2. **原子写**：任何新增的 manifest 写入路径必须走 `Manifest.save()`（tmp+replace），禁止直接 `write_text`。
3. **评分后端选择**：`--backend auto` 永不断流；对比实验须统一 backend（syncnet 与 heuristic 分数不可比）。
4. **SyncNet 分数只做批次内相对比较**：score_norm 绝对值无跨项目意义（conf 量级依赖视频内容）。
5. **导入规范**：syncnet 必须从 `syncnet_python.syncnet_pipeline` 子模块导入；diffsynth 走 editable 安装（IDE 配置见下节）。
6. **设备显式化**：所有 device 参数传 `torch.device("mps")` 对象而非字符串（DiffSynth 内部兼容性）。

### 7.3 IDE / 静态检查配置（已验证有效）

```json
    "${workspaceFolder}/scripts/lib",

  ],
  "basedpyright.analysis.typeCheckingMode": "standard",
```

## 8. 故障排除指南（Troubleshooting）

### 8.1 快速诊断表

| 症状 | 根因 | 处置 | 详见 |
| ---- | ---- | ---- | ---- |
| IDE 报 `无法解析导入 "diffsynth..."` | editable 安装 finder 语言服务器不执行 + basedpyright 不读 `python.analysis.*` | settings.json 加 `basedpyright.analysis.extraPaths`（见 7.3） | 02-避坑 §IDE |
| 运行时 `ModuleNotFoundError: h3_common` | 脚本从子目录运行时 `sys.path.insert` 相对路径失效 | 统一用 `Path(__file__).resolve().parents[N] / "lib"` | 02-避坑 §导入 |
| `syncnet_score` 恒返回 None | ① 权重缺失 ② scenedetect≥0.7 ③ scene 分段 0 成轨 | ① 补权重到 models/syncnet ② `pip install "scenedetect<0.7"` ③ 已用全局 `_track` 绕过（保持现状） | 02-避坑 §SyncNet |
| NF4 加载报 bitsandbytes 错 | 未装/版本不符 | `pip install bitsandbytes==0.50.2` | 01-环境 |
| MPS OOM / 水位报错 | 统一内存压力 | `PYTORCH_MPS_HIGH_WATERMARK_RATIO=0.0` 或减 batch/分辨率 | 02-避坑 §MPS |
| torch.compile 大量 recompile 警告 | bitsandbytes 反量化 kernel 形状多样 | 无害，忽略（或 `torch._dynamo.config.cache_size_limit` 调大） | 02-避坑 §性能 |
| 生成中途断电/中断 | — | 直接重跑 `batch_ref2va_nf4.py --batch XX`，SUCCESS 自动跳过 | 03-流水线 |
| av_offset 报 -10~-15 帧 | 音画相位观察项（非错误） | 人工核验主观错位感；确认后再研究推理侧对齐 | 06 §性能风险 |
